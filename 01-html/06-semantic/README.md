## 1. מה זו סמנטיקה?

### 📖 ההסבר

**סמנטי = בעל משמעות.**

</div>

```html
<!-- ❌ "Div Soup" – למחשב זה חסר משמעות -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="main">
  <div class="article">...</div>
</div>
<div class="footer">...</div>

<!-- ✅ סמנטי – המחשב מבין את המבנה -->
<header>
  <nav>...</nav>
</header>
<main>
  <article>...</article>
</main>
<footer>...</footer>
```

<div dir="rtl" align="right">

**התוצאה הוויזואלית זהה לגמרי.** ההבדל הוא במי שקורא את הקוד:

| מי | מה מרוויח מסמנטיקה |
|-----|---------------------|
| **קורא מסך** | יכול לנווט: "קפוץ לתוכן הראשי", "רשימת הכותרות", "אזורי הדף" |
| **מנוע חיפוש** | מבין מה התוכן המרכזי ומה תפריט. משפיע ישירות על הדירוג |
| **הדפדפן** | מציע "מצב קריאה" שמסתיר את כל מה שאינו `<article>` |
| **מפתח אחר** | מבין את המבנה במבט אחד, בלי לקרוא את ה-CSS |

### 🌍 מהעולם האמיתי

**הטענה "התוצאה זהה" נשמעת כמו תירוץ להתעצל. בואו נראה שהיא לא.**

**ניסוי 1 – מצב קריאה בדפדפן.** פתחו כתבה באתר חדשות גדול, והפעילו
"מצב קריאה" (בפיירפוקס: האייקון בשורת הכתובת; בכרום דרך תוסף או
`Ctrl+Shift+P` → Reading). כל הפרסומות, התפריטים והסרגלים נעלמים,
ונשארת הכתבה בלבד.

**איך הדפדפן ידע מה הכתבה?** הוא חיפש `<article>` ו-`<main>`.
באתר שבנוי מ-`<div class="article">` מצב הקריאה פשוט **לא עובד**,
או שהוא לוקח את התוכן הלא נכון.

**ניסוי 2 – ראו את "אזורי הדף" בעצמכם.** הריצו את זה בקונסול
(F12 → Console) על כל אתר:

</div>

```js
document.querySelectorAll('header,nav,main,article,section,aside,footer')
  .forEach(el => console.log(el.tagName, '→', el.textContent.trim().slice(0,50)));
```

<div dir="rtl" align="right">

באתר בנוי היטב תראו מפה ברורה של הדף. באתר שבנוי מ-div – רשימה ריקה.
**זו בדיוק הרשימה שקורא מסך נותן למשתמש עיוור לניווט מהיר.**

**ולמה `class="header"` לא עוזר?** כי המחלקה היא **המצאה פרטית שלכם**.
מפתח אחר יקרא לה `topbar`, שלישי `site-head`. אף מכונה בעולם לא מכירה
את שלושתן. `<header>` היא **חלק מהתקן** – כל דפדפן, כל קורא מסך וכל
מנוע חיפוש בעולם מבינים אותה, זהה, מאז 2011.

### ✋ תרגול מיידי

המירו את הקוד לסמנטי:

</div>

```html
<div class="top">
  <div class="menu">...</div>
</div>
<div class="content">
  <div class="post">...</div>
</div>
<div class="sidebar">...</div>
<div class="bottom">...</div>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<header>
  <nav>...</nav>
</header>
<main>
  <article>...</article>
</main>
<aside>...</aside>
<footer>...</footer>
```

<div dir="rtl" align="right">

**שימו לב שמספר השורות זהה, וההזחה זהה.** לא הוספנו שום מורכבות –
רק החלפנו שם גנרי בשם בעל משמעות.

**ומה עם ה-CSS?** אפשר לעצב `header { ... }` בדיוק כמו `.top { ... }`.
לא איבדנו כלום, והרווחנו נגישות, SEO וקריאוּת.

**המקרה היחיד שדורש מחשבה:** `<aside>` – האם התוכן הצדדי באמת "צדדי"?
אם זה סרגל עם קישורים קשורים או פרסומות – כן. אם זו עמודה שנייה של
התוכן המרכזי – היא שייכת ל-`<main>`.

</div>
</details>

<div dir="rtl" align="right">

## 2. שלד הדף – התגיות המבניות

### 📖 ההסבר

</div>

```
┌─────────────────────────────────────────────┐
│  <header>                                   │
│    <nav> ... </nav>                         │
│  </header>                                  │
├──────────────────────────┬──────────────────┤
│  <main>                  │  <aside>         │
│    <article>             │                  │
│      <section> ... </>   │   תוכן צדדי      │
│      <section> ... </>   │                  │
│    </article>            │                  │
│  </main>                 │                  │
├──────────────────────────┴──────────────────┤
│  <footer>                                   │
└─────────────────────────────────────────────┘
```

<div dir="rtl" align="right">

| תגית | תפקיד | כמה בדף? |
|-------|--------|-----------|
| `<header>` | ראש הדף או ראש של אזור | כמה (אחד ראשי) |
| `<nav>` | תפריט ניווט | כמה |
| `<main>` | התוכן הראשי והייחודי | **אחד בלבד** |
| `<article>` | תוכן שעומד בפני עצמו | כמה |
| `<section>` | קטע נושאי בעל כותרת | כמה |
| `<aside>` | תוכן צדדי / משני | כמה |
| `<footer>` | תחתית הדף או של אזור | כמה |
| `<figure>` `<figcaption>` | מדיה עם כיתוב | כמה |
| `<address>` | פרטי קשר | כמה |
| `<time>` | תאריך/שעה במבנה מכונה | כמה |
| `<details>` `<summary>` | תוכן מתקפל | כמה |
| `<mark>` | סימון | כמה |

### 🌍 מהעולם האמיתי

**`<header>` ו-`<footer>` אינם רק "למעלה" ו"למטה" – הם יחסיים להקשר.**

זו הנקודה שהכי מפתיעה תלמידים: **מותר להם להופיע כמה פעמים בדף**,
כי לכל `<article>` יכול להיות ראש ותחתית משלו:

</div>

```html
<body>
  <header>                              <!-- הראש של האתר -->
    <h1>הבלוג של דנה</h1>
    <nav>...</nav>
  </header>

  <main>
    <article>
      <header>                          <!-- הראש של הכתבה -->
        <h2>איך למדתי לתכנת</h2>
        <p>מאת דנה · <time datetime="2026-03-01">1 במרץ</time></p>
      </header>

      <p>התוכן...</p>

      <footer>                          <!-- התחתית של הכתבה -->
        <p>תגיות: לימודים, תכנות</p>
      </footer>
    </article>
  </main>

  <footer>                              <!-- התחתית של האתר -->
    <p>&copy; 2026</p>
  </footer>
</body>
```

<div dir="rtl" align="right">

**ה"תחתית" של הכתבה יושבת באמצע הדף** – וזה תקין לחלוטין. השם `footer`
מתאר את התפקיד ביחס לאזור שמכיל אותו, לא את המיקום על המסך.

**איפה תראו את זה בכל אתר חדשות:** לכל כתבה יש שם כותב, תאריך וקטגוריה
בראש (`<header>`), ותגיות, שיתוף ותגובות בסוף (`<footer>`).

**`<nav>` – לא כל קבוצת קישורים היא `<nav>`.** הוא נועד ל**בלוקי ניווט
עיקריים**: התפריט הראשי, פירורי לחם (breadcrumbs), דפדוף בין עמודים.
שלושה קישורים בתוך פסקה הם פשוט קישורים.

אם יש כמה `<nav>` בדף, תנו לכל אחד שם:

</div>

```html
<nav aria-label="ניווט ראשי">...</nav>
<nav aria-label="פירורי לחם">...</nav>
<nav aria-label="קישורי כותרת תחתונה">...</nav>
```

<div dir="rtl" align="right">

בלי זה, משתמש קורא מסך שומע "ניווט, ניווט, ניווט" ולא יודע להבדיל.

### ✋ תרגול מיידי

איזו תגית לכל אזור?

1. הלוגו והתפריט בראש כל דף
2. פרסומת בצד הדף
3. פרטי הצלם מתחת לתמונה בכתבה
4. הכתבה עצמה
5. כתובת המשרד בתחתית האתר

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | התגית | הערה |
|---|--------|-------|
| 1 | `<header>` + `<nav>` בתוכו | הראש של האתר |
| 2 | `<aside>` | תוכן שקשור בעקיפין, ניתן להסרה בלי לפגוע בתוכן |
| 3 | `<figcaption>` בתוך `<figure>` | הכיתוב שייך לתמונה, לא לדף |
| 4 | `<article>` | עומדת בפני עצמה |
| 5 | `<address>` בתוך `<footer>` | `<address>` היא לפרטי קשר |

**נקודה על 5:** `<address>` היא **לא** לכל כתובת דואר. היא לפרטי הקשר
של **בעל התוכן** – האתר או המאמר. כתובת של מסעדה בתוך ביקורת עליה
היא טקסט רגיל, לא `<address>`.

</div>
</details>

<div dir="rtl" align="right">

## 3. `<article>` מול `<section>` מול `<div>`

### 📖 ההסבר

זו השאלה הכי נפוצה במודול. הנה מבחן פשוט:

| שאלה | התשובה |
|-------|---------|
| האם התוכן **הגיוני בפני עצמו** אם אעתיק אותו לאתר אחר? | → `<article>` |
| האם זהו **קטע נושאי** בתוך משהו גדול יותר, עם כותרת משלו? | → `<section>` |
| האם אני צריך את זה **רק כדי לעצב** ב-CSS? | → `<div>` |

</div>

```html
<main>
  <h1>הבלוג שלי</h1>

  <!-- כל פוסט הוא article - הוא עומד בפני עצמו -->
  <article>
    <header>
      <h2>איך למדתי לתכנת</h2>
      <p>מאת דנה כהן · <time datetime="2026-03-01">1 במרץ 2026</time></p>
    </header>

    <!-- בתוך המאמר, section מחלק לקטעים נושאיים -->
    <section>
      <h3>ההתחלה</h3>
      <p>...</p>
    </section>

    <section>
      <h3>הקושי הראשון</h3>
      <p>...</p>
    </section>

    <footer>
      <p>תגיות: לימודים, תכנות</p>
    </footer>
  </article>
</main>
```

<div dir="rtl" align="right">

> ⚠️ **כלל חשוב:** ל-`<section>` צריכה להיות **כותרת**.
> אם אין כותרת טבעית – כנראה שזה `<div>`.

### 🌍 מהעולם האמיתי – "מבחן ההעתקה"

**השאלה המדויקת שתפתור לכם כל התלבטות:**

> *"אם אשלוף את התוכן הזה ואשים אותו בניוזלטר, בפיד RSS או בטוויטר –
> הוא עדיין יהיה מובן?"*

| התוכן | מובן לבד? | התגית |
|--------|------------|--------|
| פוסט בבלוג | ✅ כן | `<article>` |
| מוצר בחנות (תמונה, שם, מחיר) | ✅ כן | `<article>` |
| תגובה של משתמש | ✅ כן – היא עומדת בפני עצמה | `<article>` |
| כרטיס חדשות בעמוד הבית | ✅ כן | `<article>` |
| "אודותינו" בדף הבית | ❌ לא – "אודות **מי**?" | `<section>` |
| "פרק 3" במדריך | ❌ לא – חסר ההקשר | `<section>` |
| עטיפה שמרכזת תוכן ב-CSS | ❌ אין לה תוכן משלה | `<div>` |

**המקרה שהכי מפתיע: תגובה של משתמש היא `<article>`.**
"אבל היא תלויה בפוסט!" – לא באמת. תגובה עם שם המגיב, תאריך ותוכן
עומדת בפני עצמה כיחידת תוכן. ולכן פיד תגובות באתר חדשות בנוי
מ-`<article>`-ים מקוננים בתוך ה-`<article>` של הכתבה.

**וההיפך – מבחן שקובע שזה `<div>`:** אם הסרתם את התגית והתוכן נשאר
מובן לחלוטין, ורק העיצוב התקלקל – זה היה `<div>`. תפקידו היחיד היה עיצוב.

### ✋ תרגול מיידי

`<article>`, `<section>` או `<div>`?

1. מתכון בודד באתר מתכונים
2. אזור "המרכיבים" בתוך המתכון
3. עטיפה שנותנת רקע אפור לכל האזור
4. ביקורת של משתמש על המתכון
5. אזור "מתכונים דומים"

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | התגית | הנימוק |
|---|--------|---------|
| 1 | `<article>` | מתכון שלם מובן לבד. אפשר לשתף אותו. |
| 2 | `<section>` | "מרכיבים" בלי המתכון חסר משמעות. יש לו כותרת. |
| 3 | `<div>` | תפקיד עיצובי בלבד. |
| 4 | `<article>` | ביקורת עם שם, דירוג ותאריך עומדת בפני עצמה. |
| 5 | `<aside>` | תוכן קשור אך משני. אפשר להסיר בלי לפגוע במתכון. |

**המבנה המלא:**

</div>

```html
<article>                          <!-- המתכון -->
  <h1>עוגת שוקולד</h1>

  <section>
    <h2>מרכיבים</h2>
    <ul>...</ul>
  </section>

  <section>
    <h2>אופן ההכנה</h2>
    <ol>...</ol>
  </section>

  <section>
    <h2>ביקורות</h2>
    <article>                      <!-- ביקורת בודדת -->
      <h3>דנה כהן</h3>
      <p>יצא מעולה!</p>
    </article>
  </section>
</article>

<aside>
  <h2>מתכונים דומים</h2>
</aside>
```

<div dir="rtl" align="right">

**שימו לב ל-`<article>` בתוך `<article>`** – זה תקין לחלוטין ונפוץ מאוד.
כל תגובה היא יחידה עצמאית בתוך יחידה עצמאית גדולה יותר.

</div>
</details>

## 4. `<main>` – התגית שהכי חשוב לזכור

### 📖 ההסבר

</div>

```html
<body>
  <header>...</header>
  <nav>...</nav>

  <main>
    <!-- כאן, ורק כאן, התוכן הייחודי של הדף הזה -->
  </main>

  <footer>...</footer>
</body>
```

<div dir="rtl" align="right">

**כללים:**
- **אחד בלבד** בדף.
- לא בתוך `<article>`, `<aside>`, `<header>`, `<footer>` או `<nav>`.
- מכיל רק תוכן **ייחודי לדף הזה** – לא תפריט שחוזר בכל הדפים.

### 🌍 מהעולם האמיתי

**המבחן שמגדיר מה נכנס ל-`<main>`:**

> *"האם התוכן הזה זהה גם בדף אחר באתר?"*
> אם כן – הוא **מחוץ** ל-`<main>`.

| הרכיב | בתוך `<main>`? |
|--------|-----------------|
| התפריט הראשי | ❌ – חוזר בכל דף |
| הלוגו | ❌ |
| הכתבה / התוכן של הדף | ✅ |
| טופס יצירת קשר בדף "צור קשר" | ✅ – זה **התוכן** של הדף |
| כותרת תחתונה עם זכויות יוצרים | ❌ |
| סרגל "הכי נקראים" | ❌ – `<aside>` |

**למה זה כל כך קריטי? נסו את זה:**

1. פתחו אתר כלשהו.
2. הקישו `Tab` שוב ושוב, בלי לגעת בעכבר.

תראו את המיקוד עובר על **כל קישור בתפריט**, אחד-אחד, לפני שתגיעו
לתוכן. באתר עם תפריט של 25 קישורים – זה 25 לחיצות Tab.
**בכל דף מחדש.**

עכשיו תארו לעצמכם שזו הדרך היחידה שלכם לגלוש. זו המציאות של משתמשי
מקלדת ושל אנשים עם מגבלה מוטורית.

`<main>` נותן לקורא המסך נקודת קפיצה: פקודה אחת ואתה בתוכן.
בשילוב עם **קישור דילוג** (סעיף 6), גם משתמשי מקלדת רואים מיד מוצא.

### ✋ תרגול מיידי

מה לא בסדר כאן?

</div>

```html
<body>
  <main>
    <header>
      <nav>תפריט האתר</nav>
    </header>
    <article>הכתבה</article>
  </main>
  <main>
    <aside>פרסומות</aside>
  </main>
</body>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

**שלוש בעיות:**

| # | הבעיה | למה |
|---|--------|------|
| 1 | **שני `<main>`** | מותר אחד בלבד. הדפדפן לא ידע לאן "לקפוץ לתוכן". |
| 2 | **התפריט בתוך `<main>`** | הוא חוזר בכל דף – הוא לא תוכן ייחודי. |
| 3 | **`<aside>` בתוך `<main>`** | פרסומות הן תוכן משני, לא התוכן הראשי. |

</div>

</body>

הוא יזעק על שני `<main>`. וב-Lighthouse (F12 → Lighthouse → Accessibility)
תקבלו ציון נגישות שמשקף את המבנה.

## 5. `<details>` ו-`<summary>` – אקורדיון בלי JavaScript

### 📖 ההסבר

</div>

```html
<details>
  <summary>מה כלול במחיר?</summary>
  <p>המחיר כולל את כל 28 המפגשים, חומרי הלימוד וליווי אישי.</p>
</details>

<details open>
  <summary>האם נדרש ידע קודם?</summary>
  <p>לא. הקורס מתחיל מאפס.</p>
</details>
```

<div dir="rtl" align="right">

התגית `open` פותחת את הפריט כברירת מחדל.

### 🌍 מהעולם האמיתי

**זו התגית שחוסכת הכי הרבה קוד ביחס לגודלה.**

לפני שהיא הייתה קיימת, "אקורדיון" של שאלות נפוצות דרש:

| מה היה צריך | כמה |
|--------------|------|
| HTML למבנה | ~10 שורות |
| CSS להסתרה והצגה | ~15 שורות |
| JavaScript ללחיצה | ~20 שורות |
| טיפול במקלדת (Enter/Space) | ~10 שורות |
| תכונות ARIA (`aria-expanded`) | עוד כמה |

**היום:** שתי תגיות. וזה מגיע **נגיש מהקופסה** – עובד עם מקלדת,
קורא מסך מכריז "מכווץ/מורחב", ונשמר במצב הנכון.

**בונוס שאנשים לא מכירים:** `Ctrl+F` בדפדפן **מוצא טקסט גם בתוך
`<details>` סגור**, ופותח אותו אוטומטית. פתרון JavaScript ביתי
לא יעשה את זה.

**וזה עובד גם כאן, בדף שאתם קוראים** – כל "💡 הצגת הפתרון" במסמך הזה
הוא `<details>`. GitHub תומך בו ישירות ב-Markdown.

**איפה תראו את זה:** שאלות נפוצות, "קרא עוד" בטקסט ארוך, פרטים
טכניים מתקדמים, ספויילרים בביקורות, ופירוט הזמנה בעמוד תשלום.

### ✋ תרגול מיידי

בנו אקורדיון של 3 שאלות נפוצות על הקורס, כשהראשונה פתוחה.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<section>
  <h2>שאלות נפוצות</h2>

  <details open>
    <summary>כמה זמן נמשך הקורס?</summary>
    <p>28 מפגשים, סה״כ 112 שעות לימוד.</p>
  </details>

  <details>
    <summary>האם צריך ידע קודם?</summary>
    <p>לא. הקורס מתחיל מאפס ומניח שאין רקע בתכנות.</p>
  </details>

  <details>
    <summary>האם לומדים גם בסיסי נתונים?</summary>
    <p>לא בקורס הזה. SQL נלמד בקורס נפרד.</p>
  </details>
</section>
```

<div dir="rtl" align="right">

**שלוש נקודות:**

1. **`<summary>` חייב להיות הילד הראשון** של `<details>`. אחרת הדפדפן
   ייצור לבד "Details" באנגלית.
2. **`open` רק על הראשון** – מראה למשתמש איך הרכיב עובד.
   אם הכול סגור, חלק מהמשתמשים לא יבינו שיש שם תוכן.
3. **הכול עטוף ב-`<section>` עם `<h2>`** – זה קטע נושאי בדף.

</div>
</details>

## 6. נגישות (Accessibility / a11y)

### 📖 ההסבר

**נגישות = שהאתר יהיה שמיש לכולם**, כולל אנשים עם מוגבלות ראייה,
שמיעה, מוטוריקה או קוגניציה.

| עיקרון | מה עושים |
|---------|-----------|
| **טקסט חלופי** | `alt` לכל תמונה משמעותית |
| **היררכיית כותרות** | `h1` אחד, בלי דילוגים |
| **תוויות בטפסים** | `<label for>` לכל שדה |
| **ניווט במקלדת** | כל פעולה זמינה בעזרת `Tab` ו-`Enter` |
| **ניגודיות צבעים** | יחס 4.5:1 לפחות בין טקסט לרקע |
| **שפת הדף** | `<html lang="he">` |
| **טקסט קישור ברור** | "קראו על מדיניות הפרטיות", לא "לחצו כאן" |
| **לא רק צבע** | אל תסמנו שגיאה בצבע אדום בלבד – הוסיפו אייקון או טקסט |

### 🌍 מהעולם האמיתי

**נגישות היא לא "טובה" – בישראל היא חוק.**

**תקנות שוויון זכויות לאנשים עם מוגבלות (התאמות נגישות לשירות)**
מחייבות אתרים של גופים ציבוריים ועסקים לעמוד בתקן הישראלי
**ת״י 5568**, המבוסס על **WCAG 2.0 ברמה AA**. אי-עמידה חושפת
לתביעות ולקנסות.

**ובעולם הרחב** – התביעה נגד רשת Domino's בארה״ב הגיעה עד לבית המשפט
העליון (2019), שקבע שאתר הוא "מקום ציבורי" לכל דבר. אלפי תביעות
נגישות מוגשות שם מדי שנה.

**אבל הנתון שכדאי לזכור הוא אחר:** כ-**20% מהאוכלוסייה** חיה עם
מוגבלות כלשהי. אתר לא נגיש לא "מפספס מיעוט קטן" – הוא מפספס אחד
מכל חמישה לקוחות פוטנציאליים.

**ורוב ההתאמות עוזרות לכולם:**

| ההתאמה | למי היא נועדה | מי עוד נהנה |
|---------|----------------|--------------|
| כתוביות | חירשים | כל מי שצופה בסרטון באוטובוס |
| ניגודיות גבוהה | לקויי ראייה | כל מי שמסתכל על הטלפון בשמש |
| ניווט במקלדת | מגבלה מוטורית | מפתחים, משתמשים מהירים |
| טקסט קישור ברור | קוראי מסך | כל מי שסורק דף בעיניים |

זה נקרא **"אפקט מדרכת השפה"**: המדרכה המשופעת נבנתה לכיסאות גלגלים,
ומשמשת היום עגלות תינוק, מזוודות ועגלות קניות.

### 🔨 שלב אחר שלב – בדיקת נגישות ב-3 דקות

**שלב 1 – בדיקת מקלדת (30 שניות, בלי כלים).**
הניחו את העכבר בצד. הקישו `Tab` דרך כל הדף. שאלו:
- אני **רואה** איפה המיקוד נמצא? (אם לא – מישהו כתב `outline: none`)
- הסדר הגיוני?
- הגעתי לכל כפתור וקישור?

**שלב 2 – Lighthouse (דקה).**
F12 → לשונית **Lighthouse** → סמנו **Accessibility** → Analyze.
תקבלו ציון ורשימת בעיות עם הסבר. **יעד: 100.**

**שלב 3 – בדיקת כותרות (30 שניות).** הריצו בקונסול:

</div>

```js
document.querySelectorAll('h1,h2,h3,h4,h5,h6')
  .forEach(h => console.log(h.tagName, h.innerText));
```

<div dir="rtl" align="right">

האם יש `h1` אחד? יש דילוגים?

**שלב 4 – בדיקת ניגודיות.** F12 → בחרו טקסט → בלשונית Styles לחצו על
ריבוע הצבע. כרום מציג את יחס הניגודיות וסימן ✓ או ✗ מול התקן.

> ⚠️ **Lighthouse מוצא רק כ-30% מבעיות הנגישות.** הוא לא יכול לדעת
> אם ה-`alt` שכתבתם **נכון**, רק שהוא קיים. אין תחליף לבדיקה ידנית.

### קישור דילוג

</div>

```html
<body>
  <a href="#main-content" class="skip-link">דלגו לתוכן הראשי</a>

  <header>
    <nav><!-- 30 קישורים --></nav>
  </header>

  <main id="main-content">
    ...
  </main>
</body>
```

<div dir="rtl" align="right">

זהו הקישור **הראשון** בדף. הוא מוסתר ויזואלית ומופיע רק בלחיצה על `Tab`.

**נסו:** היכנסו לכל אתר ממשלתי או לאתר חדשות גדול, לחצו `Tab` פעם אחת
מיד עם טעינת הדף. יקפוץ קישור "דלג לתוכן" שלא ראיתם קודם. זה בדיוק זה.

### ARIA – מתי (ובעיקר: מתי לא)

</div>

```html
<!-- ✅ תגית סמנטית - עדיף תמיד -->
<button>שלח</button>

<!-- ❌ div + ARIA - הרבה עבודה, פחות טוב -->
<div role="button" tabindex="0" aria-pressed="false">שלח</div>
```

<div dir="rtl" align="right">

> **כלל ARIA הראשון:** *אל תשתמשו ב-ARIA אם יש תגית HTML שעושה את זה.*

**למה?** `<button>` נותן לכם **בחינם**: מיקוד ב-Tab, הפעלה ב-Enter
וב-Space, הכרזה נכונה בקורא מסך, מצב `:disabled`, ושליחת טופס.
עם `<div role="button">` אתם צריכים לממש כל אחד מהם ידנית –
ולרוב תשכחו לפחות אחד.

**נתון מהתעשייה:** סקר WebAIM השנתי מוצא שוב ושוב שדפים **עם** ARIA
סובלים בממוצע מ**יותר** שגיאות נגישות מדפים בלעדיו. ARIA שגוי גרוע
מ-ARIA חסר – הוא **משקר** לקורא המסך.

תכונות ARIA שכן שימושיות:

| תכונה | מתי |
|--------|------|
| `aria-label` | כשאין טקסט גלוי, למשל כפתור עם אייקון בלבד |
| `aria-labelledby` | קישור לאלמנט שמשמש כתווית |
| `aria-describedby` | קישור להסבר נוסף |
| `aria-hidden="true"` | להסתיר אלמנט דקורטיבי מקוראי מסך |
| `aria-live="polite"` | להכריז על תוכן שמשתנה דינמית |
| `role="alert"` | הודעת שגיאה דחופה |

</div>

```html
<!-- כפתור עם אייקון בלבד – בלי aria-label הוא "כפתור" חסר שם -->
<button aria-label="סגירת החלון">✕</button>

<!-- אייקון דקורטיבי ליד טקסט – aria-hidden מונע כפילות -->
<p><span aria-hidden="true">📧</span> צרו קשר</p>

<!-- אזור שמתעדכן דינמית – קורא המסך יכריז על השינוי -->
<div aria-live="polite" id="cart-count">3 פריטים בסל</div>
```

<div dir="rtl" align="right">

### ✋ תרגול מיידי

מצאו **4 בעיות נגישות**:

</div>

```html

  <div onclick="send()">שלח</div>
  <img src="chart.png">
  <a href="/privacy">לחצו כאן</a>
  <h1>ראשי</h1>
  <h4>משנה</h4>
</body>
</html>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | הבעיה | ההשלכה | התיקון |
|---|--------|----------|---------|
| 1 | חסר `lang` ב-`<html>` | קורא המסך יקריא עברית במבטא אנגלי | `<html lang="he" dir="rtl">` |
| 2 | `<div onclick>` במקום `<button>` | לא נגיש ב-Tab, לא מגיב ל-Enter, לא מוכרז ככפתור | `<button onclick="send()">` |

## 7. SEO – מטא-תגיות

### 📖 ההסבר

</div>

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <!-- כותרת: 50-60 תווים. מופיעה בגוגל ובלשונית -->
  <title>קורס Full Stack בעברית | מכללת עתיד</title>

  <!-- תיאור: 150-160 תווים. מופיע מתחת לכותרת בגוגל -->
  <meta name="description"
        content="קורס Full Stack מלא בעברית: HTML, CSS ו-JavaScript. 28 מפגשים, ליווי אישי ופרויקט גמר.">

  <!-- כתובת קנונית - מונעת תוכן כפול -->
  <link rel="canonical" href="https://example.com/course">

  <!-- ===== Open Graph: כך הקישור נראה בפייסבוק / וואטסאפ ===== -->
  <meta property="og:title" content="קורס Full Stack בעברית">
  <meta property="og:description" content="למדו לבנות אתרים מאפס.">
  <meta property="og:image" content="https://example.com/preview.jpg">
  <meta property="og:url" content="https://example.com/course">
  <meta property="og:type" content="website">

  <!-- ===== Twitter Card ===== -->
  <meta name="twitter:card" content="summary_large_image">
</head>
```

<div dir="rtl" align="right">

> ⚠️ שימו לב: `og:` משתמש ב-**`property=`**, בעוד ש-`description`
> משתמש ב-**`name=`**. זו הסיבה מספר 1 לתצוגה מקדימה שבורה בוואטסאפ.

### 🌍 מהעולם האמיתי

**Open Graph הוא מה שקורה כשאתם מדביקים קישור בוואטסאפ.**

שלחתם קישור והופיע ריבוע יפה עם תמונה, כותרת ותיאור? זה Open Graph.
הופיעה רק כתובת אפורה וארוכה? האתר לא הגדיר אותו.

**וזה משנה דרמטית.** קישור עם תצוגה מקדימה מקבל הרבה יותר לחיצות
מקישור עירום. עבור עסק שמפיץ קישורים בוואטסאפ ובפייסבוק, זה ההבדל
בין קמפיין שעובד לקמפיין שלא.

**איך בודקים לפני שמפרסמים:**

| הכלי | לאיזו רשת |
|-------|------------|
| [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) | פייסבוק, וואטסאפ |
| [Twitter Card Validator](https://cards-dev.twitter.com/validator) | X/טוויטר |
| [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/) | לינקדאין |

הם גם **מנקים מטמון** – חשוב, כי הרשתות שומרות את התצוגה המקדימה
ולא יעדכנו אותה לבד אחרי שתתקנו.

**ה-`<title>` – מה שרואים בגוגל.** נסו לחפש משהו בגוגל ולהסתכל על
תוצאה כלשהי. השורה הכחולה = `<title>`. הטקסט האפור מתחתיה =
`meta description`. **אלה כל מה שיש לכם כדי לגרום למישהו ללחוץ.**

| הכלל | למה |
|-------|------|
| `<title>` – 50–60 תווים | יותר מזה, גוגל חותך עם "..." |
| `description` – 150–160 תווים | אותו דבר |
| ייחודי **לכל דף** | 50 דפים עם אותו title = גוגל לא יודע איזה להציג |
| מילת המפתח קרוב להתחלה | מה שנחתך בסוף פחות חשוב |

> ⚠️ **`meta keywords` מת.** גוגל התעלם ממנו מאז 2009 בגלל ניצול לרעה.
> אם ראיתם אותו במדריך – המדריך ישן.

**ו-`canonical`?** אם אותו תוכן נגיש בכמה כתובות
(`/product?id=5`, `/product/5`, `/product/5?ref=facebook`) –
גוגל רואה שלושה דפים כפולים ומעניש. `canonical` אומר לו:
"הכתובת האמיתית היא זו".

### ✋ תרגול מיידי

כתבו `<head>` מלא לדף מוצר של נעלי ריצה בחנות אונליין.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <title>נעלי ריצה אסיקס ג׳ל – משלוח חינם | ספורט פלוס</title>

  <meta name="description"
        content="נעלי ריצה אסיקס ג׳ל לגברים, בולם זעזועים מתקדם. מידות 39-46, משלוח חינם עד הבית תוך 3 ימי עסקים. 30 יום להחזרה.">

  <link rel="canonical" href="https://sportplus.co.il/shoes/asics-gel">

  <meta property="og:type"        content="product">
  <meta property="og:title"       content="נעלי ריצה אסיקס ג׳ל">
  <meta property="og:description" content="בולם זעזועים מתקדם, משלוח חינם.">
  <meta property="og:image"       content="https://sportplus.co.il/img/asics-gel.jpg">
  <meta property="og:url"         content="https://sportplus.co.il/shoes/asics-gel">

  <meta name="twitter:card" content="summary_large_image">
</head>
```

<div dir="rtl" align="right">

**מה מייחד את הכתיבה הזו:**

| הבחירה | הנימוק |
|---------|---------|
| שם המוצר **בתחילת** ה-`title` | זה מה שיישאר אם גוגל יחתוך |
| "משלוח חינם" ב-`title` | טריגר ללחיצה, לא רק תיאור |
| `description` עם מידות, זמן משלוח ומדיניות החזרה | עונה על השאלות שמונעות קנייה |
| `og:type="product"` | לא `website` – זה דף מוצר |
| `og:image` בכתובת **מוחלטת** | פייסבוק לא מבין נתיבים יחסיים |

**הטעות הנפוצה ב-`og:image`:** לכתוב `content="/img/shoe.jpg"`.
זה לא יעבוד. חייב `https://` מלא.

</div>
</details>

    <h2>מאמרים נוספים</h2>
  </aside>

    <address>צרו קשר: <a href="mailto:info@site.com">info@site.com</a></address>

  </footer>

</body>

### תרגיל 4 – תיקון נגישות 🟡

**קובץ:** [`exercises/ex4-fix-accessibility.html`](exercises/ex4-fix-accessibility.html) ·
[פתרון](solutions/ex4-fix-accessibility.html)

בקובץ יש דף עם **10 בעיות נגישות**. מצאו, תקנו, וכתבו בהערה מה הייתה הבעיה.

רמזים למה לחפש: `lang`, `alt`, היררכיית כותרות, `<label>`, טקסט קישור,
`div` שמתפקד ככפתור, `outline: none`, `<main>` חסר, טבלה לפריסה,
כפתור אייקון בלי שם.

**🌍 למה זה תרגיל אמיתי:** זו בדיוק העבודה של "התאמת נגישות" –
משימה שנשכרים אליה מפתחים בכל חברה בישראל בגלל דרישות החוק.
ורוב הבעיות שתמצאו כאן הן הבעיות הנפוצות ביותר בפועל.

**בדיקה:** הריצו Lighthouse (F12 → Lighthouse → Accessibility).
**היעד: ציון 100.** ואז עשו גם בדיקת Tab ידנית מסעיף 6 –
Lighthouse לא תופס הכול.

**🔗 מתבסס על:** [סעיף 6 – נגישות](#6-נגישות-accessibility--a11y)

### תרגיל 5 – אתגר: דף אתר מלא ⭐

**קובץ:** [`exercises/ex5-complete-page.html`](exercises/ex5-complete-page.html) ·
[פתרון](solutions/ex5-complete-page.html)

בנו דף בית מלא לעסק לבחירתכם (מספרה, מסעדה, סטודיו יוגה), הכולל:

**מבנה:**
- [ ] קישור דילוג
- [ ] `<header>` + `<nav>` עם `aria-label`
- [ ] `<main>` יחיד
- [ ] לפחות 3 `<section>` בעלי כותרות
- [ ] לפחות 2 `<article>`
- [ ] `<aside>`
- [ ] `<footer>` עם `<address>`
- [ ] `<figure>` + `<figcaption>`
- [ ] `<details>`/`<summary>` לשאלות נפוצות (לפחות 3)
- [ ] `<time>` עם `datetime`
- [ ] טופס יצירת קשר נגיש

**נגישות:**
- [ ] `lang` ו-`dir` תקינים
- [ ] היררכיית כותרות ללא דילוגים
- [ ] `alt` לכל תמונה
- [ ] `<label>` לכל שדה
- [ ] טקסט קישור משמעותי
- [ ] `aria-label` לכפתור אייקון

**SEO:**
- [ ] `<title>` ייחודי (50–60 תווים)
- [ ] `meta description` (150–160 תווים)
- [ ] 4 תגיות Open Graph לפחות
- [ ] `link canonical`

**🌍 למה זה תרגיל אמיתי:** זהו **דף אמיתי לעסק אמיתי**.
כל מה שנדרש כאן הוא מה שלקוח משלם עליו: אתר שנמצא בגוגל,
נראה טוב כשמשתפים אותו בוואטסאפ, ועומד בדרישות החוק לנגישות.

**יעדים:** Lighthouse – נגישות 100, SEO 100.
[validator.w3.org](https://validator.w3.org) – 0 שגיאות.
