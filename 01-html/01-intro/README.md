## 1. איך עובד האינטרנט?

### 📖 ההסבר

כשאתם מקלידים `www.google.com` בדפדפן, קורה התהליך הבא:

</div>

```
┌─────────────┐   1. בקשה (Request)    ┌─────────────┐
│             │  ────────────────────▶  │             │
│   דפדפן     │                         │    שרת      │
│  (Client)   │  ◀────────────────────  │  (Server)   │
│             │   2. תשובה (Response)   │             │
└─────────────┘   HTML + CSS + JS       └─────────────┘
       │
       │ 3. הדפדפן "מרנדר" את הקבצים
       ▼
   הדף שאתם רואים על המסך
```

<div dir="rtl" align="right">

**המושגים החשובים:**

| מושג | הסבר |
|------|-------|
| **Client (לקוח)** | הדפדפן שלכם. הוא מבקש קבצים. |
| **Server (שרת)** | מחשב שמאחסן את קבצי האתר ומחזיר אותם. |
| **HTTP** | ה"שפה" שבה הלקוח והשרת מדברים. |
| **URL** | הכתובת של המשאב, לדוגמה `https://example.com/about.html` |
| **Rendering** | תהליך שבו הדפדפן הופך קוד לתמונה על המסך. |

### 🌍 מהעולם האמיתי

**המסעדה.** אתם יושבים בשולחן (הדפדפן). אתם מזמינים מהמלצר "פסטה" (בקשת HTTP).
המלצר הולך למטבח (השרת), המטבח מכין ומחזיר צלחת (התשובה). אתם לא רואים את המטבח
ולא יודעים איך הוא בנוי – אתם רואים רק את הצלחת.

**עכשיו תראו את זה בעצמכם, על אתר אמיתי:**

1. פתחו את [ynet.co.il](https://www.ynet.co.il).
2. הקישו `F12` → לשונית **Network**.
3. רעננו את הדף (`F5`).

תראו רשימה של **מאות** שורות. כל שורה היא בקשה נפרדת: קובץ HTML אחד, אחריו קובצי
CSS, קובצי JavaScript, ועשרות תמונות. דף חדשות "אחד" הוא בפועל מאות בקשות לשרת.

בעמודה **Status** תראו את המספר `200` – זה קוד ה-HTTP ל"הכול תקין". את `404`
("הדף לא נמצא") אתם כבר מכירים מהחיים.

> 💡 **נקודה חשובה:** כשאתם פותחים קובץ HTML מהמחשב בלחיצה כפולה, אין שרת בכלל –
> הדפדפן קורא ישירות מהדיסק, ותראו בשורת הכתובת `file:///` במקום `https://`.
> זה עובד לרוב התרגילים, אבל בהמשך (במודול Fetch) נצטרך שרת אמיתי,
> ולכן אנחנו משתמשים ב-**Live Server**.

### ✋ תרגול מיידי

פתחו את לשונית Network באתר כלשהו, ומצאו: **כמה בקשות** נשלחו בסך הכול,
ומה **הקובץ הראשון** ברשימה.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

מספר הבקשות מופיע בשורת הסיכום בתחתית הלשונית (למשל `247 requests`).

**הקובץ הראשון הוא תמיד מסמך ה-HTML** (הסוג `document`). זה הגיוני: הדפדפן חייב
לקרוא קודם את ה-HTML כדי לדעת אילו קובצי CSS, JS ותמונות לבקש אחריו.

זו בדיוק הסיבה ש-HTML הוא השלד: כל השאר תלוי בו.

</div>
</details>

## 2. שלוש הטכנולוגיות של צד הלקוח

### 📖 ההסבר

לכל אתר בעולם יש שלוש שכבות:

| טכנולוגיה | תפקיד | אנלוגיה לגוף האדם |
|------------|--------|-------------------|
| **HTML** | תוכן ומבנה | השלד |
| **CSS** | עיצוב ומראה | העור והבגדים |
| **JavaScript** | התנהגות ואינטראקציה | השרירים והמוח |

**HTML** = HyperText Markup Language – שפת **סימון** (Markup), לא שפת תכנות.
אין בה משתנים, אין תנאים ואין לולאות. תפקידה היחיד: לתאר לדפדפן **מה** יש בדף.

### 🌍 מהעולם האמיתי

**כפתור "הוספה לסל" באתר קניות** – שלוש השכבות בפעולה, על אלמנט אחד:

| השכבה | מה היא תורמת לכפתור | מה יקרה בלעדיה |
|--------|---------------------|-----------------|
| **HTML** | שיש כאן כפתור, ושכתוב עליו "הוספה לסל" | אין כפתור בכלל |
| **CSS** | שהוא כתום, מעוגל, ומשנה גוון במגע עכבר | כפתור אפור מכוער של הדפדפן – אבל **עדיין עובד** |
| **JavaScript** | שבלחיצה המוצר באמת נכנס לסל והמספר למעלה עולה | כפתור יפה שלא עושה כלום |

**נסו את זה:** היכנסו לאתר קניות כלשהו והקישו `Ctrl+Shift+M` (או F12 ואז אייקון
הנייד). זה מדמה מסך טלפון. שימו לב שהאתר **מסתדר מחדש** – עמודות הופכות לשורות,
התפריט מתקפל. ה-HTML לא השתנה באף תו. רק ה-CSS הגיב לרוחב המסך.

זהו הרעיון המרכזי: **הפרדת אחריות**. כל שכבה עושה דבר אחד.

### ✋ תרגול מיידי

היכנסו לאתר כלשהו, פתחו F12 ולחצו על לשונית **Network**. בתוך הרשימה, סננו לפי
`CSS` ומחקו את קובץ ה-CSS מהזיכרון: לחצו על אייקון ה-🚫 (Clear) ואז בלשונית
**Elements** מצאו את תגית ה-`<link rel="stylesheet">` ומחקו אותה (Delete).

מה קרה לאתר? ומה **עדיין** עובד בו?

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

האתר "מתפרק" ונראה כמו מסמך Word משנות ה-90: טקסט שחור על רקע לבן, קישורים
כחולים ומקווקווים, תמונות אחת מתחת לשנייה.

**אבל – והנה העיקר – כל התוכן עדיין שם.** כל הכותרות, כל הפסקאות, כל הקישורים.
הם אפילו עדיין **עובדים**: לחיצה על קישור עדיין מנווטת.

זו ההוכחה החיה ש-HTML הוא השלד. בלי CSS האתר מכוער; בלי HTML אין אתר.

זו גם הסיבה שנגישות מתחילה ב-HTML: קורא מסך של אדם עיוור "רואה" את האתר בדיוק
כמו שראיתם אותו עכשיו – בלי עיצוב, רק מבנה.

</div>
</details>

## 3. מבנה מסמך HTML

### 📖 ההסבר

זהו השלד שכל קובץ HTML חייב להכיל. נבנה אותו יחד, שכבה-שכבה.

### 🔨 שלב אחר שלב

**שלב 1 – מצהירים שזה HTML5.** תמיד השורה הראשונה בקובץ:

</div>

```html
<!DOCTYPE html>
```

<div dir="rtl" align="right">

**שלב 2 – פותחים את תגית השורש.** כל שאר הדף ייכנס לתוכה:

</div>

```html
<!DOCTYPE html>
<html lang="he" dir="rtl">
</html>
```

<div dir="rtl" align="right">

**שלב 3 – מוסיפים שני חדרים.** לכל מסמך HTML יש בדיוק שניים:
`<head>` (מידע **על** הדף – לא נראה) ו-`<body>` (מה שרואים):

</div>

```html
<!DOCTYPE html>
<html lang="he" dir="rtl">
<head>
</head>
<body>
</body>
</html>
```

<div dir="rtl" align="right">

**שלב 4 – ממלאים את ה-`<head>`.** שלוש שורות שחוזרות בכל דף בעולם:

</div>

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>הכותרת שמופיעה בלשונית</title>
</head>
```

<div dir="rtl" align="right">

**שלב 5 – כותבים תוכן ב-`<body>`.** רק עכשיו יופיע משהו על המסך:

</div>

```html
<body>
  <h1>שלום עולם</h1>
  <p>זו הפסקה הראשונה שלי.</p>
</body>
```

<div dir="rtl" align="right">

### 💻 הקוד המלא

</div>

```html
<!DOCTYPE html>
<html lang="he" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>הכותרת שמופיעה בלשונית</title>
</head>
<body>

  <h1>שלום עולם</h1>
  <p>זו הפסקה הראשונה שלי.</p>

</body>
</html>
```

<div dir="rtl" align="right">

**מה יופיע על המסך:**

</div>

```
┌──────────────────────────────────────────┐
│ 🌐 הכותרת שמופיעה בלשונית    ✕           │  ← ה-<title>
├──────────────────────────────────────────┤
│                                          │
│                            שלום עולם     │  ← <h1>, גדול ומודגש
│                                          │
│                  זו הפסקה הראשונה שלי.   │  ← <p>, טקסט רגיל
│                                          │
└──────────────────────────────────────────┘
```

<div dir="rtl" align="right">

### מה כל שורה עושה?

| שורה | תפקיד |
|------|--------|
| `<!DOCTYPE html>` | אומר לדפדפן: "זה מסמך HTML5". חובה, תמיד ראשון. |
| `<html>` | תגית השורש. כל הדף בתוכה. |
| `lang="he"` | מצהיר שהשפה עברית. חשוב לקוראי מסך ולמנועי חיפוש. |
| `dir="rtl"` | כיוון הכתיבה מימין לשמאל. **קריטי לאתרים בעברית.** |
| `<head>` | מידע **על** הדף. לא נראה למשתמש. |
| `<meta charset="UTF-8">` | קידוד תווים. **בלי זה העברית תופיע כג׳יבריש.** |
| `<meta name="viewport" ...>` | גורם לדף להיראות נכון בנייד. |
| `<title>` | הטקסט בלשונית הדפדפן ובתוצאות החיפוש. |
| `<body>` | כל מה שהמשתמש **רואה** בדף. |

### 🌍 מהעולם האמיתי

**ה-`<title>` הוא לא קישוט – הוא שווה כסף.**

הטקסט שאתם כותבים ב-`<title>` הוא:
- הטקסט בלשונית הדפדפן,
- **השורה הכחולה בתוצאות החיפוש בגוגל**,
- שם הסימנייה כשמישהו שומר את הדף,
- מה שמופיע כשמעבירים קישור בוואטסאפ.

לכן `<title>מסמך ללא שם</title>` באתר אמיתי הוא נזק עסקי ישיר.
אתר מקצועי יכתוב `<title>נעלי ריצה לגברים – משלוח חינם | שם החנות</title>`.

**וה-`<meta charset="UTF-8">`?** תיכנסו ל[כל אתר ישראלי](https://www.gov.il),
הקישו `Ctrl+U` (הצג מקור), וחפשו את השורה. היא שם. תמיד. בלי יוצא מן הכלל –
כי בלעדיה כל האתר היה מוצג כג׳יבריש.

> ⚠️ **טעות נפוצה מס׳ 1:** לשכוח `<meta charset="UTF-8">` ואז לראות `×××` במקום עברית.
> ⚠️ **טעות נפוצה מס׳ 2:** לכתוב תוכן בתוך `<head>` במקום `<body>` ולהתפלא שהוא לא מופיע.

### 🚀 קיצור דרך: Emmet

ב-VS Code, בקובץ `.html` ריק, הקלידו סימן קריאה `!` ולחצו `Tab`.
כל השלד נוצר אוטומטית. אחר כך רק מוסיפים `dir="rtl"` ומשנים `lang` ל-`he`.

### ✋ תרגול מיידי

צרו קובץ `index.html`, בנו בו שלד מלא, ותנו לו כותרת "התיק שלי".
בגוף הדף כתבו את שמכם ככותרת ראשית ומשפט אחד עליכם.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<!DOCTYPE html>
<html lang="he" dir="rtl">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>התיק שלי</title>
</head>
<body>

  <h1>דנה לוי</h1>
  <p>סטודנטית לפיתוח אתרים, אוהבת עיצוב וקפה.</p>

</body>
</html>
```

<div dir="rtl" align="right">

**בדיקה עצמית:** שמרו, פתחו ב-Live Server. אם העברית מופיעה תקין ובלשונית
הדפדפן כתוב "התיק שלי" – עשיתם הכול נכון.

</div>
</details>

## 4. תגיות (Tags) ואלמנטים (Elements)

### 📖 ההסבר

</div>

```html
<p>שלום כיתה</p>
│ │      │     │
│ │      │     └── תגית סוגרת (Closing tag)
│ │      └──────── תוכן (Content)
│ └─────────────── שם התגית
└───────────────── תגית פותחת (Opening tag)

    כל השורה ביחד = אלמנט (Element)
```

<div dir="rtl" align="right">

**המילון:** "תגית" היא הסימן `<p>`. "אלמנט" הוא הדבר השלם – פתיחה, תוכן וסגירה.

### תגיות ריקות (Void Elements)

יש תגיות שאין להן תוכן, ולכן **אין להן תגית סוגרת**:

</div>

```html
<br>       <!-- ירידת שורה -->
<hr>       <!-- קו מפריד אופקי -->
<img src="cat.jpg" alt="חתול">   <!-- תמונה -->
<input type="text">              <!-- שדה קלט -->
<meta charset="UTF-8">           <!-- מטא-מידע -->
```

<div dir="rtl" align="right">

**איך לזכור:** אם התגית **עוטפת** משהו – היא צריכה סגירה. אם היא **היא עצמה**
הדבר – אין מה לסגור. `<p>` עוטפת טקסט; `<img>` *היא* התמונה.

### 🌍 מהעולם האמיתי

**כל דף שראיתם בחייכם הוא עץ של אלמנטים.** בואו נראה את זה:

1. פתחו את [ויקיפדיה](https://he.wikipedia.org).
2. לחצו קליק ימני על **כותרת** הערך → "בדוק" / Inspect.

נפתחת לשונית Elements, והכותרת מסומנת. תראו משהו כמו:

</div>

```html
<h1 id="firstHeading" class="firstHeading">ישראל</h1>
```

<div dir="rtl" align="right">

זהו. זה בדיוק מה שלמדתם עכשיו: תגית פותחת, שתי תכונות, תוכן, תגית סוגרת.
האתר הגדול בעולם בנוי מאותן לבנים בדיוק שאתם לומדים עכשיו.

**עכשיו עשו משהו כיפי:** לחצו לחיצה כפולה על הטקסט "ישראל" בתוך הלשונית,
שנו אותו לשם שלכם, והקישו Enter. הכותרת בדף השתנתה. 😄

(אל תיבהלו – שיניתם רק את העותק שבזיכרון הדפדפן שלכם. רענון יחזיר הכול.
זו בדיוק ההוכחה שהדפדפן בונה **עץ אלמנטים** בזיכרון מתוך ה-HTML שקיבל.)

### ✋ תרגול מיידי

כמה **אלמנטים** יש בקוד הבא, וכמה מהם **ריקים**?

</div>

```html
<body>
  <h1>כותרת</h1>
  <hr>
  <p>פסקה עם <br> ירידת שורה</p>
  <img src="a.jpg" alt="תמונה">
</body>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

**6 אלמנטים**, מתוכם **3 ריקים**.

| האלמנט | ריק? |
|---------|------|
| `<body>` | ❌ – עוטף את כל השאר |
| `<h1>` | ❌ |
| `<hr>` | ✅ |
| `<p>` | ❌ |
| `<br>` | ✅ (נמצא **בתוך** ה-`<p>` – זה קינון, ונדבר עליו בסעיף 6) |
| `<img>` | ✅ |

**הטעות הנפוצה:** לשכוח לספור את `<body>`. גם היא אלמנט לכל דבר.

</div>

## 5. תכונות (Attributes)

### 📖 ההסבר

תכונה היא מידע נוסף שנותנים לתגית. היא נכתבת **בתגית הפותחת בלבד**.

</div>

```html
<a href="https://google.com" target="_blank">לחצו כאן</a>
   └──┬──┘ └────────┬───────┘ └──────┬─────┘
      │             │                │
   שם התכונה     הערך          תכונה נוספת
```

<div dir="rtl" align="right">

**כללים:**

- הערך תמיד בתוך **מרכאות**: `href="..."`.
- מפרידים בין תכונות ב**רווח**, לא בפסיק.
- שמות תכונות תמיד באותיות **קטנות**.

**תכונות גלובליות** – עובדות כמעט על כל תגית:

| תכונה | שימוש |
|--------|--------|
| `id` | מזהה **ייחודי** לאלמנט אחד בדף |
| `class` | שם קבוצה, יכול לחזור על הרבה אלמנטים |
| `title` | טקסט שמופיע בריחוף עכבר |
| `style` | עיצוב ישיר (נלמד ב-CSS, ומומלץ להימנע) |
| `dir` | כיוון כתיבה: `rtl` / `ltr` |

### 🌍 מהעולם האמיתי

**התכונה `alt` בתמונה היא לא "עוד תכונה" – היא הבדל בין נגיש ללא נגיש.**

בכל אתר חדשות, לכל תמונה יש `alt`. למה?

| מי צריך את זה | למה |
|----------------|------|
| **משתמש עיוור** | קורא המסך מקריא את ה-`alt` במקום התמונה. בלעדיו הוא שומע "תמונה" – ותו לא. |
| **מי שהאינטרנט שלו איטי** | התמונה לא נטענה? במקומה מופיע טקסט ה-`alt`. |
| **גוגל** | גוגל לא "רואה" תמונות. ה-`alt` הוא הדרך היחידה שלו לדעת מה בתמונה. זה מה שמכניס אתרים לחיפוש תמונות. |

**מקרה מפורסם:** בשנת 2019 נתבעה רשת הפיצריות Domino's בארה״ב בבית המשפט העליון
בדיוק בגלל זה – אתר שלא היה נגיש לקוראי מסך. בית המשפט קבע שאתר הוא "מקום ציבורי"
לכל דבר. תכונה אחת חסרה = תביעה משפטית.

**נסו:** באתר כלשהו, קליק ימני על תמונה → Inspect. תראו את ה-`alt`.
אם הוא ריק או חסר – מצאתם באג נגישות באתר אמיתי.

### ✋ תרגול מיידי

מצאו **3 שגיאות** בשורה הבאה:

</div>

```html
<A HREF=https://example.com, Target="_blank">לחצו</a>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | השגיאה | התיקון |
|---|---------|---------|
| 1 | הערך של `href` **בלי מרכאות** | `href="https://example.com"` |
| 2 | **פסיק** בין התכונות | להחליף ברווח |
| 3 | אותיות **גדולות** (`A`, `HREF`, `Target`) | הכול באותיות קטנות |

**הקוד המתוקן:**

</div>

```html
<a href="https://example.com" target="_blank">לחצו</a>
```

<div dir="rtl" align="right">

**הערה:** דפדפנים מודרניים סלחניים ויתקנו חלק מזה בעצמם. אל תסמכו על זה –
קוד לא עקבי הוא קוד שקשה לתחזק, ובקבצים גדולים זה מקור לבאגים אמיתיים.

</div>
</details>

## 6. קינון (Nesting)

### 📖 ההסבר

תגיות יכולות להיות בתוך תגיות. **הסדר חייב להיות הפוך בסגירה:**

</div>

```html
<!-- ✅ נכון -->
<p>זהו טקסט <strong>מודגש</strong> בתוך פסקה</p>

<!-- ❌ שגוי – סדר סגירה הפוך -->
<p>זהו טקסט <strong>מודגש</p></strong>
```

<div dir="rtl" align="right">

חשבו על זה כמו סוגריים במתמטיקה: מה שנפתח אחרון – נסגר ראשון.

**טיפ לקריאות:** הזיחו (indent) כל רמת קינון ב-2 רווחים.

</div>

```html
<body>
  <div>
    <h1>כותרת</h1>
    <p>פסקה</p>
  </div>
</body>
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**קופסאות בתוך קופסאות – בדיוק כמו במעבר דירה.**

ארגז "מטבח" מכיל ארגז "כלים", שמכיל שקית "סכו״ם". אף פעם לא תסגרו את ארגז
"המטבח" **לפני** שסגרתם את הארגז שבתוכו. זה פיזית בלתי אפשרי. HTML זהה.

**וכך זה נראה בכל אתר קניות בעולם** – כרטיס מוצר:

</div>

```html
<div class="product-card">          <!-- הכרטיס כולו   -->
  <img src="shoe.jpg" alt="נעל">    <!--   התמונה      -->
  <div class="product-info">        <!--   אזור הפרטים -->
    <h3>נעלי ריצה</h3>              <!--     השם        -->
    <p class="price">₪299</p>       <!--     המחיר      -->
    <button>הוספה לסל</button>      <!--     הכפתור     -->
  </div>                            <!--   סוגר פרטים   -->
</div>                              <!-- סוגר כרטיס     -->
```

<div dir="rtl" align="right">

שימו לב איך **ההזחה מציירת את המבנה**. אתם רואים בעין אחת מה נמצא בתוך מה.
זו לא קוסמטיקה – בקובץ של 800 שורות, הזחה נכונה היא ההבדל בין קוד שאפשר לתחזק
לבין סיוט.

**נסו:** פתחו כל אתר, F12 → Elements. תראו משולשים קטנים ▸ ליד אלמנטים.
כל משולש הוא קינון. פתחו וסגרו אותם – אתם מנווטים בעץ המסמך.

### ✋ תרגול מיידי

תקנו את הקינון:

</div>

```html
<div>
  <p>שלום <strong>עולם</p></strong>
</div>

```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<div>
  <p>שלום <strong>עולם</strong></p>
</div>

```

<div dir="rtl" align="right">

**הכלל:** `<strong>` נפתח **אחרון**, ולכן חייב להיסגר **ראשון**.

**איך לוודא שלא טעיתם:** ב-VS Code, שימו את הסמן על תגית פותחת. VS Code יסמן
בקו את התגית הסוגרת שלה. אם היא לא במקום שציפיתם – יש בעיית קינון.

</div>
</details>

<div dir="rtl" align="right">

## 7. הערות (Comments)

### 📖 ההסבר

טקסט שהדפדפן מתעלם ממנו. משמש לתיעוד ולביטול קוד זמנית.

</div>

```html
<!-- זו הערה. היא לא תופיע בדף. -->

<!--
  אפשר גם
  על כמה שורות
-->

<!-- <p>הפסקה הזו מבוטלת זמנית</p> -->
```

<div dir="rtl" align="right">

**קיצור מקלדת ב-VS Code:** מסמנים שורות ולוחצים `Ctrl + /`.

### 🌍 מהעולם האמיתי

הערות משמשות שני דברים בעבודה יומיומית:

**1. סימון אזורים בקובץ ארוך.** בקובץ של 500 שורות:

</div>

```html
<!-- ===== HEADER ===== -->
...
<!-- ===== תפריט ניווט ===== -->
...
<!-- ===== FOOTER ===== -->
```

<div dir="rtl" align="right">

**2. "לכבות" קוד בזמן חיפוש באג.** במקום למחוק בלוק ולגלות שהיה לו צורך –
מנטרלים אותו בהערה, בודקים, ומחזירים.

> ⚠️ **אזהרת אבטחה:** הערות **נראות** לכל אחד. הקישו `Ctrl+U` באתר כלשהו
> ותראו את כל ההערות של המפתחים. אף פעם אל תכתבו בהערה סיסמה, מפתח API,
> כתובת של דף ניהול, או "TODO: לתקן את פרצת האבטחה בשורה 40".
>
> זה קרה. הרבה פעמים. האקרים מחפשים בדיוק את זה.

### ✋ תרגול מיידי

היכנסו לאתר כלשהו, הקישו `Ctrl+U`, והקישו `Ctrl+F` כדי לחפש `<!--`.
מצאו הערה אחת אמיתית שמפתח השאיר.

</div>

<details dir="rtl">
<summary><b>💡 מה בדרך כלל מוצאים</b></summary>

<div dir="rtl" align="right">

בדרך כלל תמצאו אחד מאלה:

| סוג | דוגמה |
|-----|--------|
| **סימון אזורים** | `<!-- Start Header -->` |
| **הערות של כלים** | `<!-- Generated by WordPress 6.4 -->` |
| **קוד מנוטרל** | `<!-- <div class="banner">...</div> -->` |
| **קרדיטים** | `<!-- Built by ... -->` |

שימו לב במיוחד להערות מהסוג השני: `Generated by WordPress 6.4` מגלה לתוקף
בדיוק באיזו גרסה האתר משתמש – וממנה קל לחפש פרצות ידועות. זו דוגמה מצוינת
ל"דליפת מידע" תמימה לכאורה.

</div>
</details>

## 8. עברית ו-RTL – נקודות חשובות

### 📖 ההסבר

לאתר בעברית צריך שלושה דברים:

</div>

```html
<html lang="he" dir="rtl">     <!-- 1. שפה וכיוון -->
<meta charset="UTF-8">          <!-- 2. קידוד -->
```

<div dir="rtl" align="right">

3. **טקסט מעורב** – כשמערבבים עברית ואנגלית/מספרים, לפעמים הסדר "קופץ".
   הפתרון: לעטוף את החלק הלועזי ב-`<span dir="ltr">`.

</div>

```html
<p>הטלפון שלי הוא <span dir="ltr">050-1234567</span> ואפשר להתקשר.</p>
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**הבעיה הזו היא לא תיאורטית – היא הכאב היומיומי של כל מפתח ישראלי.**

הדפדפן משתמש באלגוריתם בשם **BiDi** (Bidirectional) כדי להחליט מה ללכת ימינה
ומה שמאלה. הוא עובד טוב ב-95% מהמקרים, ונשבר בדיוק ב-5% שכוללים:
מספרי טלפון, כתובות אימייל, כתובות URL, סוגריים וסימני פיסוק בקצה משפט.

**דוגמה שתראו במו עיניכם.** הקוד:

</div>

```html
<p>שלחו לי מייל ל-info@example.com (בבקשה).</p>
```

<div dir="rtl" align="right">

עלול להופיע כך: `שלחו לי מייל ל-info@example.com (בבקשה)‎.` – הנקודה קופצת,
או שהסוגריים מתהפכים. התיקון:

</div>

```html
<p>שלחו לי מייל ל-<span dir="ltr">info@example.com</span> (בבקשה).</p>
```

<div dir="rtl" align="right">

**איפה זה קורה באתרים אמיתיים:** תסתכלו על כל אתר ישראלי שמציג מחירים במטבע זר,
מספרי הזמנה, או קודי קופון. אם ראיתם פעם מספר טלפון שמופיע כ-`1234567-050` –
זה בדיוק הבאג הזה, והוא הגיע לייצור.

**טיפ מקצועי נוסף:** בעברית `text-align: right` הוא לא תמיד מה שרוצים.
ב-CSS מודרני משתמשים ב-`text-align: start` – שמתאים את עצמו לכיוון הדף.
נלמד את זה בחלק ה-CSS.

### ✋ תרגול מיידי

כתבו פסקה שמכילה: משפט בעברית, מספר טלפון, ושם של אתר באנגלית –
כך שהכול יופיע בסדר הנכון.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<p>
  אפשר להתקשר אליי למספר <span dir="ltr">052-9876543</span>,
  או לבקר באתר <span dir="ltr">www.my-portfolio.com</span> לפרטים נוספים.
</p>
```

<div dir="rtl" align="right">

**הכלל הפשוט לזכור:** כל רצף תווים שאינו עברי, שנמצא **בתוך** משפט עברי –
עוטפים ב-`<span dir="ltr">`.

**דרך לבדוק:** אם הזזתם את המשפט והמספר "קפץ" למקום אחר – חסר לכם ה-span.

</div>
</details>

<div dir="rtl" align="right">

### תרגיל 3 – כרטיס ביקור 🟡

**קובץ:** [`exercises/ex3-business-card.html`](exercises/ex3-business-card.html) ·

בנו דף "כרטיס ביקור" דיגיטלי הכולל:

1. כותרת `<h1>` – שם מלא.
2. כותרת משנה `<h2>` – התפקיד שלכם (למשל "סטודנט לפיתוח Full Stack").
3. פסקה עם 3 שורות:
   - טלפון (עטוף ב-`<span dir="ltr">`)
   - אימייל (עטוף ב-`<span dir="ltr">`)

5. כותרת `<h3>` "קצת עליי" ופסקה של 2–3 משפטים.
6. הוסיפו תכונת `title` לכותרת הראשית, שתציג רמז בריחוף עכבר.
7. הוסיפו `id="card"` לכותרת ו-`class="contact"` לפסקת הקשר.
8. הוסיפו לפחות 2 הערות HTML שמסבירות את מבנה הדף.

**🔗 מתבסס על:** [סעיף 5 – תכונות](#5-תכונות-attributes), [סעיף 7 – הערות](#7-הערות-comments), [סעיף 8 – RTL](#8-עברית-ו-rtl--נקודות-חשובות)

### תרגיל 4 – מבנה מסמך מלא 🟡

**קובץ:** [`exercises/ex4-full-document.html`](exercises/ex4-full-document.html) ·
[פתרון](solutions/ex4-full-document.html)

בנו דף על נושא שאתם אוהבים (סרט, קבוצת ספורט, תחביב) הכולל:

### תרגיל 5 – אתגר: קורות חיים ⭐

**קובץ:** [`exercises/ex5-cv.html`](exercises/ex5-cv.html) ·
[פתרון](solutions/ex5-cv.html)

בנו דף קורות חיים בסיסי (רק HTML, בלי עיצוב!) הכולל:

1. שם + תפקיד מבוקש בראש הדף.
2. סעיף "פרטי קשר".
3. סעיף "השכלה" עם לפחות 2 פריטים.
4. סעיף "ניסיון תעסוקתי" עם לפחות 2 פריטים.
5. סעיף "כישורים".
6. שימוש נכון בהיררכיית כותרות (h1 → h2 → h3).
7. כל מספר, תאריך לועזי או מונח באנגלית – מטופל עם `dir="ltr"`.

**🌍 למה זה תרגיל אמיתי:** קורות חיים בפורמט HTML הם דבר שמפתחים באמת בונים
לעצמם. דף אחד, קישור אחד, נפתח בכל מכשיר, ואפשר לעדכן בשנייה. חלק ממגייסים
מעדיפים אותו על PDF.
