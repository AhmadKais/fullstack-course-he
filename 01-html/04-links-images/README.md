## 1. קישורים – `<a>`

### 📖 ההסבר

התגית שהפכה את הרשת לרשת: **Anchor** (עוגן).

</div>

```html
<a href="https://www.google.com">לחצו כאן</a>
```

<div dir="rtl" align="right">

| תכונה | תפקיד | ערכים |
|--------|--------|--------|
| `href` | היעד (חובה) | כתובת, נתיב, `#id`, `mailto:`, `tel:` |
| `target` | איפה להיפתח | `_self` (ברירת מחדל) / `_blank` (לשונית חדשה) |
| `rel` | היחס ליעד | `noopener` `noreferrer` `nofollow` |
| `download` | הורדה במקום פתיחה | שם הקובץ (אופציונלי) |
| `title` | רמז בריחוף | טקסט |

### 🌍 מהעולם האמיתי

**התגית הזו היא הסיבה שהאינטרנט נקרא "רשת".**

ב-1989 טים ברנרס-לי הציע רעיון פשוט: מסמך שיכול להצביע על מסמך אחר.
זהו. כל השאר – גוגל, ויקיפדיה, רשתות חברתיות – נבנה על הרעיון הזה.

**וזה גם איך גוגל עובד.** דירוג התוצאות בגוגל מבוסס במקורו על אלגוריתם
בשם PageRank, שסופר **כמה אתרים מקשרים אליך**. כל `<a href>` באינטרנט
הוא בעצם "הצבעה" לטובת האתר שאליו הוא מצביע.

**ולכן `rel="nofollow"` קיים:** אם אתם מקשרים למקור שאתם לא ממליצים עליו
(או לפרסומת ששילמו עליה), אתם מוסיפים `nofollow` – ואומרים לגוגל
"אני מקשר, אבל אני לא מצביע לו". אתרי חדשות ופורומים משתמשים בזה
בקישורים שמשתמשים מוסיפים, כדי למנוע ספאם.

### ⚠️ טקסט הקישור – הטעות שכולם עושים

</div>

```html
<!-- ❌ נורא -->
<p>למידע נוסף על מדיניות ההחזרות <a href="/returns">לחצו כאן</a>.</p>

<!-- ✅ טוב -->
<p>קראו את <a href="/returns">מדיניות ההחזרות שלנו</a>.</p>
```

<div dir="rtl" align="right">

**למה זה משנה?** קורא מסך מציע פקודה: "הקרא לי את כל הקישורים בדף".
משתמש עיוור שומע רשימה. אם באתר יש 12 קישורים והם כולם נקראים "לחצו כאן" –
הרשימה הזו חסרת ערך לחלוטין.

זו אחת מדרישות **תקן הנגישות הישראלי (ת״י 5568)**, שמחייב אתרים ציבוריים
ומסחריים בישראל. טקסט קישור צריך להיות מובן **מחוץ להקשר**.

### ✋ תרגול מיידי

שפרו את הקישורים האלה:

</div>

```html
<p>להורדת הקטלוג <a href="catalog.pdf">כאן</a></p>
<p>לפרטים על הקורס <a href="course.html">קראו עוד</a></p>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<p><a href="catalog.pdf">הורידו את הקטלוג (PDF)</a></p>
<p><a href="course.html">פרטים מלאים על הקורס</a></p>
```

<div dir="rtl" align="right">

**שני שיפורים בכל שורה:**

1. **טקסט הקישור מתאר את היעד** – מובן גם ברשימת קישורים מנותקת מההקשר.
2. **ציון סוג הקובץ** – "(PDF)" מזהיר את המשתמש שהקישור לא ייפתח כדף רגיל.
   באתרים מקצועיים תראו גם את גודל הקובץ: "(PDF, 2.4MB)".

**מבחן פשוט:** קראו את טקסט הקישור לבד, בלי המשפט סביבו.
אם עדיין ברור לאן הוא מוביל – הוא טוב.

</div>
</details>

<div dir="rtl" align="right">

## 2. חמשת סוגי הקישורים

### 📖 ההסבר

</div>

```html
<!-- 1. קישור חיצוני (לאתר אחר) -->
<a href="https://developer.mozilla.org" target="_blank" rel="noopener noreferrer">
  MDN – תיעוד רשמי
</a>

<!-- 2. קישור פנימי (לדף אחר באתר שלי) -->
<a href="about.html">אודות</a>
<a href="pages/contact.html">צור קשר</a>

<!-- 3. קישור לעוגן (לנקודה בתוך אותו דף) -->
<a href="#section-3">קפצו לסעיף 3</a>
...
<h2 id="section-3">סעיף 3</h2>

<!-- 4. קישור למייל -->
<a href="mailto:info@example.com">שלחו לנו מייל</a>
<a href="mailto:info@example.com?subject=פנייה מהאתר">עם נושא מוכן</a>

<!-- 5. קישור לטלפון (שימושי מאוד בנייד) -->
<a href="tel:+972501234567">050-1234567</a>
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**`tel:` – הקישור שהופך אתר לכלי עסקי.**

בכל אתר של עסק מקומי – מספרה, מוסך, מסעדה – יש כפתור "התקשרו אלינו".
בנייד, לחיצה עליו פותחת את החייגן עם המספר מוכן. זהו `tel:` וזה הכול.

**נקודה מעשית:** תמיד כתבו את המספר בפורמט בין-לאומי:

</div>

```html
<!-- ✅ עובד מכל מקום בעולם -->
<a href="tel:+972501234567">050-1234567</a>

<!-- 🟡 יעבוד רק בישראל -->
<a href="tel:0501234567">050-1234567</a>
```

<div dir="rtl" align="right">

שימו לב שה-`href` הוא בפורמט טכני, אבל **הטקסט שהמשתמש רואה** הוא בפורמט
הישראלי המוכר. זו הפרדה נכונה בין מה שהמכונה צריכה למה שהאדם קורא.

**`mailto:` עם פרמטרים** – שימושי מאוד לטפסי פנייה פשוטים:

</div>

```html
<a href="mailto:support@example.com?subject=תקלה באתר&body=שלום,%0D%0Aנתקלתי בבעיה:">
  דווחו על תקלה
</a>
```

<div dir="rtl" align="right">

זה פותח את תוכנת המייל של המשתמש עם הנושא והגוף מוכנים. `%0D%0A` הוא
ירידת שורה מקודדת.

> ⚠️ **מגבלה שחשוב להכיר:** `mailto:` עובד רק אם למשתמש **מוגדרת** תוכנת
> מייל במחשב. אם הוא משתמש בג׳ימייל בדפדפן – לא בטוח שיקרה משהו.
> לכן באתרים אמיתיים משתמשים בטופס יצירת קשר, ומציגים את המייל
> כטקסט **בנוסף** לקישור.

**`#` – קישורי עוגן.** הם מה שמפעיל:

| השימוש | הדוגמה |
|---------|---------|
| תוכן עניינים | ויקיפדיה – לחיצה על סעיף קופצת אליו |
| "חזרה לראש הדף" | `<a href="#top">` |
| ניווט בדף נחיתה ארוך | תפריט שגולל לסעיפים במקום לטעון דף חדש |
| **קישור לשיתוף** | `example.com/faq#shipping` – שולחים למישהו קישור שנוחת ישירות על השאלה הרלוונטית |

### ⚠️ אבטחה: `target="_blank"`

> **חובה:** בכל `target="_blank"` הוסיפו `rel="noopener noreferrer"`.

**למה?** בלי `noopener`, הדף שנפתח מקבל גישה לאובייקט `window.opener` –
מצביע לדף **שלכם**. אתר זדוני יכול להשתמש בזה כדי להחליף את הלשונית שלכם
בעמוד התחברות מזויף, בזמן שהמשתמש מסתכל על הלשונית החדשה.

התקיפה נקראת **Tabnabbing**. דפדפנים מודרניים כבר מוסיפים `noopener`
אוטומטית, אבל עדיין כותבים אותו במפורש – בגלל דפדפנים ישנים,
ובגלל שקוד צריך להיות מפורש.

`noreferrer` מוסיף שכבה: הוא מונע מהאתר היעד לדעת מאיזה דף הגעתם.

### ✋ תרגול מיידי

בנו את ארבעת הקישורים לכרטיס ביקור של מסעדה:
טלפון, מייל, וייז (חיצוני), וקישור לתפריט בתוך אותו דף.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<ul>
  <li><a href="tel:+97231234567">03-1234567</a></li>

  <li><a href="mailto:info@restaurant.co.il?subject=הזמנת שולחן">
        הזמנת שולחן במייל</a></li>

  <li><a href="https://waze.com/ul?q=דיזנגוף 100 תל אביב"
         target="_blank" rel="noopener noreferrer">
        ניווט עם Waze</a></li>

  <li><a href="#menu">לתפריט המסעדה</a></li>
</ul>

<h2 id="menu">התפריט שלנו</h2>
```

<div dir="rtl" align="right">

**ארבע נקודות שכדאי לשים לב אליהן:**

1. `tel:` בפורמט בין-לאומי, אבל הטקסט בפורמט מקומי.
2. `mailto:` עם `subject` – חוסך למשתמש כתיבה.
3. הקישור החיצוני **היחיד** שמקבל `target="_blank"` + `rel`.
4. `#menu` דורש `id="menu"` על אלמנט בדף. בלי ה-`id` – הקישור לא יעשה כלום.

**למה רק הקישור החיצוני נפתח בלשונית חדשה?** כי הוא היחיד שמוציא את
המשתמש מהאתר. קישור פנימי בלשונית חדשה הוא הרגל רע – הוא שובר את כפתור
"אחורה" ומציף את המשתמש בלשוניות.

</div>
</details>

<div dir="rtl" align="right">

## 3. נתיבים – החלק שהכי מבלבל

### 📖 ההסבר

נניח את מבנה התיקיות הבא:

</div>

```
my-site/
├── index.html
├── about.html
├── images/
│   ├── logo.png
│   └── team.jpg
└── pages/
    ├── contact.html
    └── services.html
```

<div dir="rtl" align="right">

### נתיב יחסי (Relative) – מומלץ

| מ-איפה | ל-איפה | הנתיב |
|---------|---------|--------|
| `index.html` | `about.html` | `about.html` |
| `index.html` | `pages/contact.html` | `pages/contact.html` |
| `index.html` | `images/logo.png` | `images/logo.png` |
| `pages/contact.html` | `index.html` | `../index.html` |
| `pages/contact.html` | `images/logo.png` | `../images/logo.png` |
| `pages/contact.html` | `pages/services.html` | `services.html` |

**הכללים:**

| סימון | משמעות |
|--------|---------|
| `file.html` | קובץ **באותה תיקייה** |
| `folder/file.html` | **תיקייה למטה** |
| `../file.html` | **תיקייה אחת למעלה** |
| `../../file.html` | שתי תיקיות למעלה |
| `/file.html` | משורש האתר (Root-relative) |

### 🔨 שלב אחר שלב – שיטת "האצבע על העץ"

זו השיטה שתציל אתכם בכל פעם. **הכלל: הנתיב תמיד מתחיל מהמקום שבו נמצא
הקובץ שכותב אותו** – לא מהשורש, ולא מאיפה שנוח.

**המשימה:** מ-`pages/contact.html`, להציג את `images/logo.png`.

**שלב 1 – איפה אני עומד?** בתוך `pages/`.

</div>

```
my-site/
├── images/
│   └── logo.png      ← לכאן אני רוצה להגיע
└── pages/
    └── contact.html  ← כאן אני נמצא 👈
```

<div dir="rtl" align="right">

**שלב 2 – אני יכול לראות את `images/` מכאן?** לא. היא לא בתוך `pages/`.
אז קודם כול צריך **לצאת החוצה**:

</div>

```
../          →  יצאתי מ-pages/, אני עכשיו ב-my-site/
```

<div dir="rtl" align="right">

**שלב 3 – עכשיו אני רואה את `images/`?** כן. נכנס אליה:

</div>

```
../images/   →  אני עכשיו בתוך images/
```

<div dir="rtl" align="right">

**שלב 4 – לוקח את הקובץ:**

</div>

```html
<img src="../images/logo.png" alt="לוגו">
```

<div dir="rtl" align="right">

**קראו את זה בקול:** *"צא החוצה, היכנס ל-images, קח את logo.png".*
אם אתם יכולים לומר את זה – הנתיב נכון.

### 🌍 מהעולם האמיתי

**למה `../` בכלל קיים ולא פשוט כותבים את הנתיב המלא?**

תארו לכם שכתבתם בכל דף באתר:

</div>

```html
<img src="C:/Users/dana/Desktop/my-site/images/logo.png">
```

<div dir="rtl" align="right">

זה יעבוד – **על המחשב שלכם בלבד**. ברגע שתעלו את האתר לשרת, כל תמונה
באתר תישבר. וזו בדיוק הטעות שכל מתחיל עושה פעם אחת, כשהוא גורר תמונה
לתוך העורך והוא מכניס נתיב מוחלט.

עם נתיבים יחסיים, **התיקייה כולה ניידת**. תוכלו לשלוח אותה במייל,
להעלות לשרת, להעביר לענן – והכול ימשיך לעבוד, כי כל קובץ מתאר את
היחס שלו לשכנים, לא את מיקומו המוחלט בעולם.

**האנלוגיה:** "הבית השלישי משמאל" (יחסי) מול "רחוב הרצל 12, תל אביב" (מוחלט).
הראשון עובד רק אם יודעים מאיפה מתחילים – אבל הוא נשאר נכון גם אם כל
השכונה עוברת מקום.

### נתיב מוחלט (Absolute)

</div>

```html
<a href="https://www.example.com/pages/contact.html">קישור מלא</a>
```

<div dir="rtl" align="right">

| סוג | מתי |
|-----|-----|
| **יחסי** | תמיד, בתוך האתר שלכם |
| **מוחלט** | רק לקישור לאתר חיצוני |

> ⚠️ **המלכודת הנפוצה ביותר בשלב הזה:** `/images/logo.png` (עם קו נטוי בהתחלה)
> **אינו** נתיב יחסי. הוא מתחיל משורש השרת. בפתיחת קובץ מהדיסק
> (`file:///`) השורש הוא כונן C – והתמונה לא תימצא.
> **הכלל בכיתה:** אל תתחילו נתיב ב-`/`.

### ✋ תרגול מיידי

לפי עץ התיקיות למעלה, מה הנתיב:

1. מ-`pages/services.html` אל `about.html`?
2. מ-`index.html` אל `images/team.jpg`?
3. מ-`pages/contact.html` אל `pages/services.html`?
4. מ-`images/` (נניח דף שם) אל `pages/contact.html`?

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | הנתיב | הקריאה בקול |
|---|--------|---------------|
| 1 | `../about.html` | "צא מ-pages, קח את about.html" |
| 2 | `images/team.jpg` | "היכנס ל-images, קח את team.jpg" |
| 3 | `services.html` | "הוא ממש כאן לידי" |
| 4 | `../pages/contact.html` | "צא מ-images, היכנס ל-pages, קח את contact.html" |

**התשובה שהכי מפספסים היא 3.** אנשים כותבים `pages/services.html` –
אבל אנחנו **כבר בתוך** `pages/`. זה היה שולח אותנו ל-`pages/pages/`.

**איך לבדוק בלי לנחש:** אם הנתיב לא עובד, פתחו את F12 → לשונית Console.
תראו שגיאת `404 Not Found` **עם הנתיב המלא** שהדפדפן ניסה לפתוח.
בדרך כלל הטעות קופצת לעין מיד.

</div>
</details>

## 4. תמונות – `<img>`

### 📖 ההסבר

</div>

```html
<img src="images/cat.jpg" alt="חתול כתום ישן על ספה" width="400" height="300">
```

<div dir="rtl" align="right">

| תכונה | חובה? | תפקיד |
|--------|--------|--------|
| `src` | ✅ | נתיב לקובץ התמונה |
| `alt` | ✅ | תיאור טקסטואלי |
| `width` / `height` | מומלץ מאוד | מונע "קפיצת" הדף בזמן הטעינה |
| `loading="lazy"` | מומלץ | טוען את התמונה רק כשמגיעים אליה |
| `title` | לא | רמז בריחוף |

### 🌍 מהעולם האמיתי

**`width` ו-`height` – התכונות שמונעות את התופעה שמעצבנת את כולם.**

אתם קוראים כתבה בטלפון. אתם מגיעים לאמצע פסקה. פתאום התוכן **קופץ למטה**
ואתם מאבדים את המקום – או גרוע מזה, לוחצים על פרסומת בטעות.

מה קרה? תמונה שהייתה עדיין בטעינה סיימה להיטען, תפסה את מקומה, ודחפה
את כל מה שמתחתיה. התופעה נקראת **CLS – Cumulative Layout Shift**,
והיא אחד ממדדי הדירוג הרשמיים של גוגל. אתר עם CLS גבוה **מדורג נמוך יותר**.

**הפתרון הוא בדיוק שתי התכונות האלה.** כשאתם מציינים `width` ו-`height`,
הדפדפן יודע **מראש** כמה מקום לשריין – עוד לפני שהתמונה ירדה:

</div>

```html
<!-- ❌ הדף יקפוץ כשהתמונה תיטען -->
<img src="hero.jpg" alt="נוף">

<!-- ✅ המקום שמור מראש. אפס קפיצה. -->
<img src="hero.jpg" alt="נוף" width="1200" height="600">
```

<div dir="rtl" align="right">

> 💡 חשוב להבין: אלה **לא** גדלי תצוגה. ה-CSS עדיין שולט בגודל בפועל
> (`max-width: 100%`). התכונות רק מוסרות לדפדפן את **יחס הגובה-רוחב**
> כדי שישריין מקום נכון.

**ו-`loading="lazy"`?** דף עם 50 תמונות מוריד את כולן מיד – גם את אלה
שנמצאות 10 מסכים למטה ואולי לעולם לא ייראו. עם `lazy`, כל תמונה יורדת
רק כשהמשתמש מתקרב אליה.

</div>

```html
<img src="photo.jpg" alt="..." loading="lazy" width="800" height="600">
```

<div dir="rtl" align="right">

> ⚠️ **אל תשימו `lazy` על התמונה הראשונה בדף.** התמונה שנראית מיד
> (above the fold) צריכה להיטען מהר ככל האפשר. `lazy` עליה רק יאט אותה.

### ✋ תרגול מיידי

מה חסר בתגית הזו, ומה יקרה בלעדיו?

</div>

```html
<img src="team-photo.jpg">
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| מה חסר | מה יקרה בלעדיו |
|---------|-----------------|
| `alt` | קורא מסך יקריא "team-photo.jpg" – שם קובץ. גוגל לא ידע מה בתמונה. אם התמונה לא נטענת, המשתמש רואה אייקון שבור. |
| `width` / `height` | הדף יקפוץ כשהתמונה תיטען (CLS). |
| `loading="lazy"` | אם היא לא התמונה הראשונה – היא תיטען מיד ותאט את הדף. |

**המתוקן:**

</div>

```html
<img src="team-photo.jpg"
     alt="שבעה עובדי החברה עומדים יחד במשרד הפתוח"
     width="1200" height="800"
     loading="lazy">
```

<div dir="rtl" align="right">

**שימו לב ל-`alt`:** הוא מתאר מה **רואים בפועל**, לא "תמונת צוות".
מישהו שלא רואה את התמונה מקבל את אותו מידע שאתם קיבלתם.

</div>
</details>

## 5. `alt` – התכונה הכי חשובה ב-`<img>`

### 📖 ההסבר

**למי זה משמש?**

1. **עיוורים** – קורא המסך מקריא את ה-`alt`.
2. **כשהתמונה לא נטענת** – הטקסט מוצג במקומה.
3. **מנועי חיפוש** – ככה גוגל "רואה" תמונות.
4. **חיסכון בנתונים** – מי שגולש עם תמונות מכובות.

### איך כותבים `alt` טוב?

| ❌ רע | ✅ טוב | למה |
|--------|---------|------|
| `alt="תמונה"` | `alt="שלושה מפתחים עובדים סביב שולחן"` | תארו מה **רואים** |
| `alt="IMG_2043.jpg"` | `alt="עוגת שוקולד מקושטת בתותים"` | שם קובץ אינו תיאור |
| `alt="תמונה של כלב"` | `alt="כלב לברדור שחור רץ על חוף הים"` | אל תכתבו "תמונה של" – ידוע שזו תמונה |

### תמונה דקורטיבית

אם התמונה היא **קישוט בלבד** (קו מפריד, רקע), משאירים `alt` **ריק**:

</div>

```html
<img src="divider.png" alt="">
```

<div dir="rtl" align="right">

> ⚠️ `alt=""` (ריק) אומר לקורא המסך "דלג עליי".
> **השמטת `alt` לגמרי** גורמת לקורא המסך להקריא את שם הקובץ – חוויה נוראית.
> ההבדל בין "ריק בכוונה" ל"חסר" הוא מהותי.

### 🌍 מהעולם האמיתי

**הכלל הזהב: `alt` תלוי בהקשר, לא בתמונה.**

אותה תמונה בדיוק תקבל `alt` שונה לגמרי לפי מה שהיא עושה בדף:

| ההקשר | ה-`alt` הנכון | למה |
|--------|----------------|------|
| תמונת נעל בקטלוג חנות | `alt="נעלי ריצה ניו באלאנס 574, אפור"` | הקונה צריך לדעת מה המוצר |
| אותה תמונה כלוגו שמקשר לדף הבית | `alt="דף הבית של ניו באלאנס"` | ה-alt מתאר את **יעד הקישור** |
| אותה תמונה כרקע דקורטיבי מאחורי טקסט | `alt=""` | היא לא מוסיפה מידע |
| אותה תמונה בכתבה על עיצוב נעליים | `alt="נעל ריצה עם סוליה עבה ולוגו N בצד"` | כאן הפרטים העיצוביים הם התוכן |

**המבחן המעשי:** *"אם הייתי מקריא את הדף בטלפון למישהו – מה הייתי אומר
במקום התמונה הזו?"* זה ה-`alt`. אם התשובה היא "כלום, זה סתם קישוט" –
אז `alt=""`.

**ובאמת נסו את זה:** בכרום, F12 → `Ctrl+Shift+P` → הקלידו "screenshot"...
או פשוט חסמו תמונות בהגדרות הדפדפן וטענו אתר. תראו את כל ה-`alt`-ים
במקום התמונות. אתרים טובים עדיין יהיו מובנים. אתרים גרועים יהיו
רשימת ריבועים ריקים.

### ✋ תרגול מיידי

כתבו `alt` לכל מקרה:

1. תמונת פרופיל של כותב מאמר
2. אייקון חץ ליד כפתור "המשך"
3. גרף עוגה של תוצאות סקר
4. לוגו החברה בכותרת, שמקשר לדף הבית

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | ה-`alt` | הנימוק |
|---|----------|---------|
| 1 | `alt="דנה לוי"` | השם מספיק. איך היא נראית לא רלוונטי לקורא. |
| 2 | `alt=""` | דקורטיבי. המילה "המשך" כבר אומרת הכול; "חץ ימינה" רק מרעיש. |
| 3 | `alt="גרף עוגה: 60% מרוצים, 25% ניטרליים, 15% לא מרוצים"` | הנתונים **הם** התוכן. חובה למסור אותם. |
| 4 | `alt="דף הבית"` או `alt="לוגו החברה – דף הבית"` | הוא בתוך `<a>`, אז ה-alt מתאר את היעד. |

**הכי מעניין הוא 3.** תמונה שמכילה **מידע** – גרף, טבלה, אינפוגרפיקה,
צילום מסך של קוד – חייבת למסור את המידע ב-`alt`. אם הוא ארוך מדי לתכונה,
כותבים תיאור קצר ב-`alt` ומוסיפים את הפירוט בטקסט לצד התמונה
(או ב-`<figcaption>`).

**`alt="גרף"` במקרה 3 הוא כישלון מוחלט** – הקורא לא מקבל שום מידע.

</div>
</details>

<div dir="rtl" align="right">

## 6. פורמטים של תמונות

### 📖 ההסבר

| פורמט | מתי משתמשים | שקיפות | אנימציה |
|--------|--------------|---------|----------|
| **JPG** | תצלומים | ❌ | ❌ |
| **PNG** | לוגו, גרפיקה, שקיפות | ✅ | ❌ |
| **SVG** | לוגו, אייקונים, גרפים | ✅ | ✅ |
| **WebP** | תחליף מודרני ל-JPG/PNG, קל יותר | ✅ | ✅ |
| **GIF** | אנימציות קצרות | חלקית | ✅ |

**SVG** הוא וקטורי – הוא נראה חד בכל גודל ומשקלו זעיר.

### 🌍 מהעולם האמיתי

**בחירת פורמט שגויה היא הסיבה מספר 1 לאתר איטי.**

תרחיש אמיתי: מעצב שולח לכם לוגו כ-PNG במשקל 2MB. אתם מטמיעים אותו.
הלוגו מופיע בכל דף באתר. משתמש בנייד עם חיבור סלולרי מוריד 2MB
**רק בשביל הלוגו**, בכל דף. אותו לוגו כ-SVG שוקל 8KB – פי 250 פחות.

**טבלת החלטה מהירה:**

| מה יש לכם | הפורמט | למה |
|------------|---------|------|
| צילום (אנשים, נוף, מוצר) | **JPG** או **WebP** | דחיסה מצוינת לגוונים רציפים |
| לוגו, אייקון, גרף, צורה גיאומטרית | **SVG** | וקטורי – חד בכל גודל, שוקל כלום |
| צילום מסך, תמונה עם טקסט חד | **PNG** | JPG "מלכלך" קצוות של טקסט |
| צריך שקיפות | **PNG**, **WebP** או **SVG** | JPG לא תומך בשקיפות |
| אנימציה קצרה | **WebP** או וידאו | GIF שוקל פי 5–10 מווידאו באיכות זהה |

**WebP הוא ברירת המחדל המודרנית.** הוא נתמך בכל הדפדפנים מאז 2020,
ושוקל בממוצע 25–35% פחות מ-JPG באותה איכות. בסעיף 8 נראה איך להגיש
אותו עם גיבוי לדפדפנים ישנים.

**נסו:** קליק ימני על תמונה בכל אתר גדול → "פתח תמונה בכרטיסייה חדשה".
הסתכלו על הסיומת בכתובת. ברוב האתרים הגדולים תראו `.webp`.

### ✋ תרגול מיידי

איזה פורמט לכל מקרה?

1. תצלום של המשרד לדף "אודות"
2. אייקון עגלת קניות
3. צילום מסך של תוכנה עם טקסט קטן
4. הלוגו של החברה

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| # | הפורמט | הנימוק |
|---|---------|---------|
| 1 | **WebP** (גיבוי JPG) | צילום = גוונים רציפים = דחיסת JPG/WebP |
| 2 | **SVG** | אייקון = צורה. יישאר חד גם ב-Retina, ואפשר לצבוע אותו ב-CSS |
| 3 | **PNG** | טקסט חד. JPG יוצר "רעש" סביב אותיות והן ייראו מטושטשות |
| 4 | **SVG** | הלוגו חייב להיראות מושלם בכל גודל – מ-32px בפאביקון ועד שלט חוצות |

**הטעות הצפויה ב-3:** לבחור JPG כי "זו תמונה". דחיסת JPG מתוכננת לצילומים,
והיא הורסת קצוות חדים. שימו זה לצד זה צילום מסך ב-JPG וב-PNG –
ההבדל בטקסט קופץ לעין.

</div>
</details>

## 7. `<figure>` ו-`<figcaption>`

### 📖 ההסבר

כשלתמונה יש כיתוב:

</div>

```html
<figure>
  <img src="chart.png" alt="גרף עמודות של מכירות לפי חודש">
  <figcaption>איור 1: מכירות רבעון ראשון 2026</figcaption>
</figure>
```

<div dir="rtl" align="right">

היתרון: הקשר בין התמונה לכיתוב מוצהר **סמנטית**, לא רק ויזואלית.

### 🌍 מהעולם האמיתי

**מה ההבדל בפועל בין זה לבין `<img>` ו-`<p>` זה מתחת לזה?**

</div>

```html
<!-- ויזואלית זהה, סמנטית מנותק -->
<img src="chart.png" alt="גרף מכירות">
<p>איור 1: מכירות רבעון ראשון</p>
```

<div dir="rtl" align="right">

בגרסה הזו, שום מכונה לא יודעת שהפסקה שייכת לתמונה. קורא מסך יקריא
תמונה, ואז פסקה עצמאית. עם `<figure>`, הוא מכריז **"איור, עם כיתוב"**
ומקשר ביניהם.

**איפה תראו את זה:**

| המקום | הדוגמה |
|--------|---------|
| ויקיפדיה | כל תמונה בסרגל הצד עם הכיתוב מתחתיה |
| מאמרים אקדמיים | "איור 1", "טבלה 3" |
| אתרי חדשות | תמונה עם קרדיט לצלם |
| תיעוד טכני | צילום מסך עם הסבר |

**נקודה שמפתיעה:** `<figure>` **אינה רק לתמונות**. היא לכל "יחידת תוכן
עצמאית עם כיתוב" – בלוק קוד, טבלה, ציטוט, סרטון:

</div>

```html
<figure>
  <pre dir="ltr"><code>const sum = (a, b) => a + b;</code></pre>
  <figcaption>דוגמה 3: פונקציית חץ בסיסית</figcaption>
</figure>
```

<div dir="rtl" align="right">

**המבחן:** אם אפשר להזיז את היחידה למקום אחר במסמך (או לנספח) בלי לשבור
את זרימת הקריאה – זו `<figure>`.

### ✋ תרגול מיידי

הוסיפו כיתוב לתמונה בצורה סמנטית נכונה:
תמונת שער של ספר, עם הכיתוב "עטיפת המהדורה הראשונה, 1954".

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<figure>
  <img src="book-cover.jpg"
       alt="עטיפת ספר ירוקה עם איור של הר ואותיות זהב"
       width="400" height="600">
  <figcaption>עטיפת המהדורה הראשונה, <time datetime="1954">1954</time></figcaption>
</figure>
```

<div dir="rtl" align="right">

**שימו לב להבחנה החשובה בין `alt` ל-`figcaption`:**

| | מה הוא עושה | מי רואה אותו |
|---|--------------|---------------|
| `alt` | מתאר **איך התמונה נראית** | רק מי שלא רואה את התמונה |
| `figcaption` | נותן **הקשר** לתמונה | **כולם** |

הם משלימים, לא כפילויות. אל תעתיקו את ה-`figcaption` ל-`alt` –
משתמש בקורא מסך ישמע את אותו טקסט פעמיים.

</div>
</details>

<div dir="rtl" align="right">

## 8. תמונות רספונסיביות

### 📖 ההסבר

### `srcset` – אותה תמונה, גדלים שונים

</div>

```html
<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w,
          photo-800.jpg 800w,
          photo-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="נוף הרים">
```

<div dir="rtl" align="right">

הדפדפן בוחר בעצמו את הקובץ המתאים לגודל המסך.

### `<picture>` – תמונות שונות לגמרי

</div>

```html
<picture>
  <!-- בנייד: תמונה מרובעת -->
  <source media="(max-width: 600px)" srcset="hero-square.jpg">
  <!-- בדסקטופ: תמונה רחבה -->
  <source media="(min-width: 601px)" srcset="hero-wide.jpg">
  <!-- גיבוי לדפדפנים ישנים – חובה! -->
  <img src="hero-wide.jpg" alt="צוות החברה">
</picture>
```

<div dir="rtl" align="right">

**גם לפורמטים מודרניים:**

</div>

```html
<picture>
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="תיאור התמונה">
</picture>
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**החישוב שמסביר למה זה קיים.**

תמונת שער של אתר בגודל 1600×900 שוקלת בערך 400KB. משתמש בטלפון
עם מסך ברוחב 390 פיקסלים מוריד אותה במלואה – ואז הדפדפן **מכווץ אותה**
לרוחב המסך. הוא הוריד 400KB כדי להציג משהו ששווה 40KB.

בחבילת גלישה, על רשת סלולרית איטית, עם 20 תמונות בדף – זה ההבדל בין
אתר שנטען בשנייה לאתר שנטען ב-12 שניות. ו-53% מהמשתמשים בנייד
נוטשים דף שלוקח יותר מ-3 שניות.

**מתי `srcset` ומתי `<picture>`? זו ההבחנה שכדאי לזכור:**

| | `srcset` | `<picture>` |
|---|----------|--------------|
| **מה משתנה** | רק ה**גודל** של אותה תמונה | ה**תמונה עצמה**, או הפורמט |
| **מי מחליט** | הדפדפן (לפי מסך, רזולוציה, ורוחב פס) | אתם, בתנאים מפורשים |
| **המקרה** | תמונת מוצר ב-3 רזולוציות | תמונת שער רחבה בדסקטופ, מרובעת ומקורבת בנייד |
| **השם המקצועי** | Resolution switching | Art direction |

**"Art direction" – למה זה נחוץ:** תמונה פנורמית של קבוצת אנשים נראית
מצוין ברוחב 1600px. באותה תמונה מכווצת לרוחב 390px, הפנים הופכות לנקודות.
הפתרון אינו להקטין – אלא להגיש **תמונה אחרת**, מקורבת, שמתמקדת בפנים.

> ⚠️ **תגית `<img>` בסוף `<picture>` היא חובה.** היא לא "גיבוי לדפדפנים
> ישנים" בלבד – היא **התגית שבאמת מוצגת**. אלמנטי `<source>` רק אומרים
> לה מאיפה לקחת את הקובץ. בלי `<img>` לא תוצג שום תמונה, ולא יהיה `alt`.

### ✋ תרגול מיידי

הגישו תמונה בפורמט WebP עם גיבוי ל-JPG, כולל `alt` וממדים.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<picture>
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg"
       alt="נוף הרי הגליל בזריחה"
       width="1200" height="675">
</picture>
```

<div dir="rtl" align="right">

**איך זה עובד:** הדפדפן קורא את ה-`<source>`-ים לפי הסדר ועוצר בראשון
שהוא תומך בו. דפדפן מודרני יראה `type="image/webp"`, יידע שהוא תומך,
וייקח את `hero.webp`. דפדפן ישן לא יזהה את הסוג, ידלג, ויגיע ל-`<img>`
עם ה-JPG.

**שלוש נקודות קריטיות:**

1. `alt` ו-`width`/`height` יושבים על ה-`<img>` – **לא** על `<picture>`
   ולא על `<source>`.
2. הסדר משנה: הפורמט המודרני **ראשון**.
3. `type` הוא מה שמאפשר לדפדפן להחליט בלי להוריד את הקובץ.

</div>
</details>

## 9. תמונה כקישור

### 📖 ההסבר

</div>

```html
<a href="index.html">
  <img src="logo.svg" alt="לוגו החברה – חזרה לדף הבית">
</a>
```

<div dir="rtl" align="right">

> 💡 כשתמונה היא קישור, ה-`alt` צריך לתאר את **יעד הקישור**, לא רק את התמונה.

### 🌍 מהעולם האמיתי

**הלוגו בפינה הוא הקישור הכי נלחץ בכל אתר.**

זו מוסכמה כה מושרשת שמשתמשים עושים את זה בלי לחשוב: רוצים לחזור לדף
הבית? לוחצים על הלוגו. אתר שלא מיישם את זה מרגיש שבור.

**וכאן נכנס הכלל של ה-`alt`:** משתמש עיוור מגיע ללוגו. אם ה-`alt` אומר
`"לוגו"` – הוא יודע שיש שם תמונה, אבל **לא יודע שזה קישור לדף הבית**.
לכן ה-`alt` חייב לתאר את הפעולה:

</div>

```html
<!-- ❌ מתאר את התמונה -->
<a href="/"><img src="logo.svg" alt="לוגו סטארטאפ בע״מ"></a>

<!-- ✅ מתאר את היעד -->
<a href="/"><img src="logo.svg" alt="סטארטאפ בע״מ – לדף הבית"></a>
```

<div dir="rtl" align="right">

**מקרה נוסף שכדאי להכיר – תמונה וטקסט באותו קישור:**

</div>

```html
<a href="/article/123">
  <img src="thumb.jpg" alt="">      <!-- ריק בכוונה! -->
  <h3>כותרת הכתבה</h3>
</a>
```

<div dir="rtl" align="right">

כאן ה-`alt` **ריק במכוון**. הכותרת כבר מסבירה לאן הקישור מוביל.
אם היה `alt` לתמונה, קורא המסך היה מקריא את התיאור ואז את הכותרת –
שתי אמירות לאותו קישור אחד. זה קורה בכל אתר חדשות עם כרטיסי כתבות.

### ✋ תרגול מיידי

מה ה-`alt` הנכון לכל מקרה?

1. תמונת מוצר שלוחצים עליה כדי לפתוח דף מוצר, **בלי** טקסט לידה
2. אותה תמונה, אבל יש שם המוצר ככותרת מתחתיה, באותו קישור

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```html
<!-- 1. התמונה היא הקישור היחיד – ה-alt נושא את כל המידע -->
<a href="/product/574">
  <img src="shoe.jpg" alt="נעלי ריצה ניו באלאנס 574 – לעמוד המוצר">
</a>

<!-- 2. יש טקסט בקישור – ה-alt מתרוקן כדי לא לכפול -->
<a href="/product/574">
  <img src="shoe.jpg" alt="">
  <h3>נעלי ריצה ניו באלאנס 574</h3>
  <p>₪449</p>
</a>
```

<div dir="rtl" align="right">

**הכלל:** בתוך קישור, `alt` ריק כאשר **יש כבר טקסט** שמסביר את היעד.
בלי טקסט – ה-`alt` הוא הדבר היחיד שיש למשתמש, והוא חייב לשאת את המידע.

**המבחן:** האזינו לקישור בקורא מסך (או קראו אותו בקול). האם נאמר אותו
דבר פעמיים? אם כן – רוקנו את ה-`alt`.

</div>
</details>

## 📋 סיכום

| תגית / תכונה | תפקיד |
|---------------|--------|
| `<a href>` | קישור |
| `target="_blank"` + `rel="noopener noreferrer"` | פתיחה בלשונית חדשה, בבטחה |
| `mailto:` / `tel:` | קישור למייל / לטלפון |
| `#id` | קישור לעוגן בדף |
| `../` | תיקייה אחת למעלה |
| `<img src alt>` | תמונה |
| `width` + `height` | מניעת קפיצת פריסה (CLS) |
| `loading="lazy"` | טעינה עצלה |
| `<figure>` `<figcaption>` | תמונה עם כיתוב |
| `srcset` | אותה תמונה, גדלים שונים |
| `<picture>` | תמונות או פורמטים שונים |
