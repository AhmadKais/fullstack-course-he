ספציפיות, ירושה והמפל

טבלת הניקוד

רכיב ניקוד
style="" (inline)1,0,0,0
#id0,1,0,0
.class, [attr], :hover0,0,1,0
תגית, ::before0,0,0,1
*0,0,0,0

ההשוואה נעשית משמאל לימין, ספרה-ספרה — כמו מספרים רגילים.

הדגמה 1: שלושה כללים, פסקה אחת

איזה צבע יהיה לי?

הכללניקודתוצאה
.demo1 p0,0,1,1❌ הובס
.demo1 .text0,0,1,0❌ הובס
.demo1 #winner0,1,0,0✅ מנצח

שימו לב: .demo1 p (ניקוד 0,0,1,1) גבוה מ- .demo1 .text (0,0,1,0)? לא! משווים משמאל: שניהם 0,0,1 — ואז 1 מול 0. אז דווקא .demo1 p מנצח את .demo1 .text. אבל שניהם מפסידים למזהה.

הדגמה 2: ניקוד זהה — האחרון מנצח

אני אדום, למרות ששני הכללים זהים בניקוד.

.tie { color: #2b6cb0; }
.tie { color: #c53030; }   /* ← מנצח: מופיע אחרון */

הדגמה 3: מזהה אחד > חמש מחלקות

אני אדום — מזהה בודד גבר על חמש מחלקות משורשרות.
.a .b .c .d .e span → 0,0,5,1 #single span → 0,1,0,0 ← מנצח

זה המקור לתסכול הנפוץ ביותר ב-CSS. לכן ההמלצה: השתמשו ב-class לעיצוב, ושמרו את id לעוגנים ול-JavaScript.

הדגמה 4: ירושה

אני סגול ונטוי — ירשתי מההורה.

גם אני. הצבע והפונט עוברים בירושה אוטומטית.

אבל את המסגרת לא ירשתי — אלא אם ביקשתי במפורש border: inherit, כמו כאן.

✅ עובר בירושה❌ לא עובר
colormargin / padding
font-family, font-sizeborder
line-heightbackground
text-alignwidth / height
directiondisplay / position

הכלל שקל לזכור: מאפייני טקסט עוברים בירושה. מאפייני קופסה לא.

הדגמה 5: !important

אני אדום — למרות שהמזהה (0,1,0,0) חזק מהמחלקה (0,0,1,0). !important גובר על הכול.

⚠️ למה להימנע מ-!important

ברגע שהשתמשתם בו, הדרך היחידה לגבור עליו היא !important נוסף — וכך נכנסים למרוץ חימוש שהופך את ה-CSS לבלתי ניתן לתחזוקה.

מה לעשות במקום: להעלות ספציפיות באופן טבעי (להוסיף מחלקת הורה), או לסדר מחדש את סדר הכללים בקובץ.

סדר ההכרעה במפל (Cascade)

  2. ספציפיות — inline > id > class > תגית
  3. סדר הופעה — האחרון מנצח
  4. ירושה מההורה
  5. ברירת המחדל של הדפדפן
