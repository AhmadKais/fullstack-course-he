## 1. מה זה CSS?

### 📖 ההסבר

**CSS** = Cascading Style Sheets – גיליונות סגנון מדורגים.

אם HTML הוא השלד, CSS הוא העור והבגדים. תפקידו היחיד: לקבוע **איך**
התוכן ייראה.

</div>

```html
<!-- HTML לבד -->
<h1>שלום</h1>
```

```css
/* CSS מוסיף את המראה */
h1 {
  color: navy;
  font-size: 40px;
  text-align: center;
}
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**האתר שמוכיח את זה בצורה הכי מרשימה: [CSS Zen Garden](http://www.csszengarden.com).**

זהו פרויקט מ-2003 שעדיין חי. יש בו **קובץ HTML אחד בדיוק** – אותו תוכן,
אותן תגיות, אותו סדר. ומעליו **מאות עיצובים** שונים לחלוטין שאנשים
תרמו לאורך השנים: אחד נראה כמו עיתון ישן, אחר כמו פוסטר יפני,
שלישי כמו ממשק מדע בדיוני.

**כל ההבדל הוא קובץ CSS אחד.** ה-HTML לא השתנה בתו אחד.

**נסו את זה גם באתר שאתם מכירים:**

1. פתחו כל אתר → F12 → לשונית **Elements**.
2. מצאו את `<link rel="stylesheet">` ב-`<head>`.
3. סמנו אותו והקישו `Delete`.

האתר "מתפרק" למסמך שחור-לבן – אבל **כל התוכן עדיין שם, וכל הקישורים
עדיין עובדים**. זה מדגים בדיוק את חלוקת התפקידים.

**וזה גם מה שקורא מסך "רואה"** – בלי עיצוב, רק מבנה. לכן HTML נכון
הוא תנאי מוקדם, ו-CSS הוא השכבה שמעליו.

## 2. שלוש דרכים לשלב CSS

### 📖 ההסבר

### א. קובץ חיצוני (External) – ✅ הדרך הנכונה

</div>

```html
<head>
  <link rel="stylesheet" href="css/style.css">
</head>
```

<div dir="rtl" align="right">

**היתרונות:** קובץ אחד משרת את כל הדפים באתר; הדפדפן שומר אותו במטמון;
הפרדה נקייה בין תוכן לעיצוב.

### ב. בתוך הדף (Internal)

</div>

```html
<head>
  <style>
    h1 { color: navy; }
  </style>
</head>
```

<div dir="rtl" align="right">

מתאים לדף בודד או לניסויים מהירים. בקורס הזה נשתמש בזה בדוגמאות
כדי שכל קובץ יהיה עצמאי.

### ג. Inline – ❌ להימנע

</div>

```html
<h1 style="color: navy;">שלום</h1>
```

<div dir="rtl" align="right">

| דרך | שימוש חוזר | תחזוקה | מתי |
|-----|-------------|---------|------|
| חיצוני | ✅ מצוין | ✅ קלה | תמיד באתר אמיתי |
| פנימי | ❌ דף אחד | 🟡 בינונית | דף בודד, לימוד |
| Inline | ❌ אלמנט אחד | ❌ קשה | כמעט אף פעם |

### 🌍 מהעולם האמיתי

**החישוב שמסביר למה קובץ חיצוני מנצח – מספרית.**

אתר עם 50 דפים וקובץ עיצוב של 100KB:

| השיטה | מה קורה |
|--------|----------|
| **CSS פנימי בכל דף** | כל דף מכיל 100KB של סגנונות. משתמש שגולש ב-10 דפים מוריד **1MB** של אותו CSS, שוב ושוב. |
| **קובץ חיצוני** | הדפדפן מוריד את ה-100KB **פעם אחת**, שומר אותו במטמון, ובכל 49 הדפים הבאים לוקח אותו מהדיסק. **0KB נוספים.** |

**וזה עוד לפני שדיברנו על תחזוקה:** רוצים לשנות את צבע המותג?
בקובץ חיצוני – שורה אחת. ב-CSS פנימי – לערוך 50 קבצים ולקוות
שלא פספסתם אחד.

**אז מתי inline כן לגיטימי?**

| המקרה | הדוגמה |
|--------|---------|
| **JavaScript שמשנה סגנון דינמית** | `element.style.width = "50%"` – סרגל התקדמות |
| **מיילים ב-HTML** | תוכנות מייל (Outlook, Gmail) מתעלמות מ-`<style>` ומקובץ חיצוני. **חייבים** inline |
| **ערך חד-פעמי שנוצר מנתונים** | גובה עמודה בגרף שמחושב מנתון |

מחוץ למקרים האלה – inline הוא חוב טכני.

### 🔨 שלב אחר שלב – מה קורה בהתנגשות?

זו שאלה שתופסת כמעט כל תלמיד. נבנה אותה מדויק.

**שלב 1 – שני כללים לאותו אלמנט, בשני מקומות:**

</div>

```css
/* בקובץ style.css */
.title { color: purple; }
```

```html
<head>
  <link rel="stylesheet" href="style.css">
  <style>
    .title { color: orange; }
  </style>
</head>
```

<div dir="rtl" align="right">

**שלב 2 – מי מנצח?** **כתום.**

**שלב 3 – למה?** רוב האנשים אומרים "כי פנימי חזק יותר מחיצוני".
**זה לא נכון.** לשני הכללים אותו סלקטור בדיוק (`.title`), ולכן
**אותה ספציפיות**. וכשהספציפיות שווה – מנצח **הכלל שנקרא אחרון**.
תגית `<style>` מופיעה **אחרי** `<link>`, אז הכלל שלה נקרא אחרון.

**שלב 4 – ההוכחה.** הפכו את הסדר:

</div>

```html
<head>
  <style>
    .title { color: orange; }
  </style>
  <link rel="stylesheet" href="style.css">   <!-- עכשיו הוא אחרון -->
</head>
```

<div dir="rtl" align="right">

עכשיו הצבע **סגול**. אותו קוד, סדר הפוך, תוצאה הפוכה.

**המסקנה:** אין "חוזק" למקום שבו נכתב ה-CSS. יש רק ספציפיות וסדר.
**היוצא מן הכלל היחיד הוא inline** – והוא מנצח בגלל ספציפיות (1,0,0,0),
לא בגלל מיקום.

### ✋ תרגול מיידי

איזה צבע יופיע?

</div>

```html
<head>
  <style> p { color: green; } </style>
  <link rel="stylesheet" href="a.css">   <!-- בפנים: p { color: blue; } -->
</head>
<body>
  <p style="color: red;">איזה צבע?</p>
</body>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

**אדום.**

| הכלל | הספציפיות | התוצאה |
|-------|------------|---------|
| `p { color: green }` (פנימי) | (0,0,0,1) | הפסיד |
| `p { color: blue }` (חיצוני, אחרון) | (0,0,0,1) | ניצח את הירוק (סדר), אבל הפסיד ל-inline |
| `style="color: red"` | **(1,0,0,0)** | **ניצח** |

**שני שלבים בהכרעה:**

1. **הירוק מול הכחול:** ספציפיות זהה → מנצח האחרון → **כחול**.
2. **הכחול מול ה-inline:** עמודת ה-inline נבדקת **ראשונה**, ושם 1 > 0 →
   **אדום**, בלי קשר לסדר.

**זו בדיוק הסיבה שinline הוא סיוט תחזוקה:** הוא מנצח כל כלל בגיליון
הסגנונות שלכם. מפתח שרואה `p { color: blue }` בקובץ ולא מבין למה
הטקסט אדום – יבזבז זמן עד שיפתח F12 ויראה את ה-`style` בתגית.

</div>
</details>

<div dir="rtl" align="right">

## 3. תחביר – אנטומיה של כלל

### 📖 ההסבר

</div>

```
סלקטור      מאפיין   ערך
   │           │       │
   ▼           ▼       ▼
   h1  {  color:  navy;  }
       │  └──────┬────┘ │
       │      הצהרה     │
       └── בלוק ההצהרות ┘
```

```css
h1 {
  color: navy;        /* הצהרה 1 */
  font-size: 40px;    /* הצהרה 2 */
  text-align: center; /* הצהרה 3 */
}
```

<div dir="rtl" align="right">

| מונח | פירוש |
|-------|--------|
| **סלקטור** (Selector) | מי מקבל את העיצוב |
| **מאפיין** (Property) | מה משנים |
| **ערך** (Value) | לאיזה ערך |
| **הצהרה** (Declaration) | `מאפיין: ערך;` |
| **כלל** (Rule) | סלקטור + בלוק הצהרות |

### 🌍 מהעולם האמיתי – למה הנקודה-פסיק כל כך מסוכנת

> ⚠️ **שכחת נקודה-פסיק שוברת את ההצהרה הבאה, לא את הנוכחית.**

</div>

```css
h1 {
  color: navy        /* ← חסרה ; */
  font-size: 40px;   /* ההצהרה הזו נבלעת ולא תעבוד */
  text-align: center;
}
```

<div dir="rtl" align="right">

**מה קורה בפועל:** הדפדפן קורא `color: navy font-size: 40px` כערך
אחד שאינו תקין, פוסל את שתי ההצהרות בשקט – וממשיך.
`text-align` דווקא יעבוד.

**התוצאה:** אתם רואים שהגודל לא השתנה, מסתכלים על `font-size`,
והוא נראה תקין לחלוטין. הבאג נמצא **בשורה שמעליו**.

**וזה הכי מבלבל כי CSS לא זורק שגיאות.** בניגוד ל-JavaScript,
CSS **מתעלם בשקט** מכל דבר שהוא לא מבין. אין הודעה, אין אזהרה.

**איך מוצאים את זה:**

| הכלי | איך |
|-------|------|
| **VS Code** | יסמן את השורה בקו גלי. שימו לב אליו. |
| **F12 → Styles** | הצהרה לא חוקית מופיעה עם ⚠️ או פשוט לא מופיעה |
| **[CSS Validator](https://jigsaw.w3.org/css-validator/)** | מוצא הכול |

**ההרגל שיציל אתכם:** נקודה-פסיק גם אחרי ההצהרה **האחרונה** בבלוק.
טכנית היא לא חובה – אבל אז כשתוסיפו הצהרה מחר, לא תשכחו אותה.

**הערות ב-CSS:**

</div>

```css
/* זו הערה */

/*
  אפשר גם
  על כמה שורות
*/
```

<div dir="rtl" align="right">

> 💡 ב-CSS יש **רק** את הצורה `/* */`. אין `//` כמו ב-JavaScript.
> `// color: red;` **אינה הערה** – היא שורה לא חוקית שתשבור את הבלוק.

## 4. סלקטורים בסיסיים

### 📖 ההסבר

</div>

```css
/* לפי תגית – כל הפסקאות בדף */
p { color: gray; }

/* לפי מחלקה – כל אלמנט עם class="highlight" */
.highlight { background: yellow; }

/* לפי מזהה – האלמנט היחיד עם id="header" */
#header { height: 80px; }

/* אוניברסלי – כל אלמנט בדף */
* { margin: 0; }
```

<div dir="rtl" align="right">

| סלקטור | סימון | דוגמה |
|---------|--------|--------|
| תגית | ללא | `p`, `h1`, `div` |
| מחלקה | נקודה | `.card` |
| מזהה | סולמית | `#nav` |
| אוניברסלי | כוכבית | `*` |

### מחלקה מול מזהה – מתי מה?

| | `class` | `id` |
|---|---------|------|
| כמה בדף | ללא הגבלה | **אחד בלבד** |
| כמה לאלמנט | כמה שרוצים | אחד |
| ספציפיות | (0,0,1,0) | (0,1,0,0) |
| שימוש מומלץ | **כמעט תמיד** | עוגנים, JavaScript |

</div>

```html
<!-- לאלמנט אחד יכולות להיות כמה מחלקות -->
<div class="card featured large">...</div>
```

```css
.card { border: 1px solid gray; }
.featured { border-color: gold; }
.large { padding: 30px; }
```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**למה מקצוענים כמעט אף פעם לא מעצבים לפי `id`?**

זה נשמע מוזר – `id` נראה מדויק ונקי. אבל:

| הבעיה | ההסבר |
|--------|--------|
| **לא ניתן לשימוש חוזר** | `id` הוא אחד בדף. יש לכם 12 כרטיסי מוצר? צריך 12 כללים כמעט זהים. |
| **הוא "מנצח" יותר מדי** | (0,1,0,0) גובר על כל מחלקה. כשתרצו לדרוס אותו – תיאלצו להוסיף עוד `id` או `!important`. |
| **הוא שביר** | מפתח JS שינה את ה-`id` כדי לחבר אירוע – והעיצוב נעלם. |

**האנלוגיה:** `id` הוא **תעודת הזהות** של האלמנט – מזהה אותו באופן
חד-חד-ערכי. `class` הוא **תיאור** – "כרטיס", "מודגש", "אזהרה".
לעיצוב אתם רוצים לתאר, לא לזהות.

**איפה `id` כן במקומו:**

| השימוש | הדוגמה |
|---------|---------|
| קישור עוגן | `<a href="#contact">` → `<section id="contact">` |
| קישור label לשדה | `<label for="email">` → `<input id="email">` |
| תפיסה ב-JavaScript | `document.getElementById("cart")` |

**נסו:** פתחו אתר גדול, F12, ותסתכלו על ה-`class`-ים.
תראו עשרות מחלקות תיאוריות ומעט מאוד `id`-ים בסלקטורים.

**ומילה על `*`:** הוא איטי יחסית (הדפדפן בודק כל אלמנט), ו**שובר ירושה**.
`* { color: black }` יצבע כל אלמנט בשחור **במפורש** – ואז `body { color: navy }`
לא יעבור בירושה לשום דבר. השימוש הלגיטימי היחיד שלו הוא איפוס:

</div>

```css
*, *::before, *::after {
  box-sizing: border-box;   /* נלמד במודול 3 */
  margin: 0;
  padding: 0;
}
```

<div dir="rtl" align="right">

### ✋ תרגול מיידי

כתבו סלקטור לכל מטרה:

1. כל הכותרות מרמה 2
2. אלמנט עם `class="btn"`
3. האלמנט עם `id="header"`
4. אלמנט שיש לו **גם** `.btn` וגם `.primary`

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```css
h2            { }   /* 1 – סלקטור תגית */
.btn          { }   /* 2 – סלקטור מחלקה */
#header       { }   /* 3 – סלקטור מזהה */
.btn.primary  { }   /* 4 – שתי מחלקות, בלי רווח! */
```

<div dir="rtl" align="right">

**הטעות הצפויה ב-4:** לכתוב `.btn .primary` **עם רווח**.
זה סלקטור אחר לגמרי – "אלמנט `.primary` שנמצא **בתוך** `.btn`".

זו הטעות מספר 1 במודול, ונקדיש לה סעיף שלם (סעיף 5).

</div>
</details>

## 5. שילוב סלקטורים

### 📖 ההסבר

</div>

```css
/* קיבוץ – אותו עיצוב לכמה סלקטורים */
h1, h2, h3 { font-family: Arial; }

/* צירוף – אלמנט p שיש לו גם class="intro" */
p.intro { font-size: 20px; }

/* שתי מחלקות יחד – חייב את שתיהן */
.card.featured { border-color: gold; }
```

<div dir="rtl" align="right">

> ⚠️ **ההבדל הקריטי ביותר במודול:**
>
> `.a .b` (**עם** רווח) = אלמנט `.b` שנמצא **בתוך** `.a`
> `.a.b` (**בלי** רווח) = אלמנט **אחד** שיש לו **את שתי המחלקות**

### 🔨 שלב אחר שלב – הרווח הוא אופרטור

**זו הנקודה שהכי הרבה תלמידים נתקעים בה. נראה את שני המקרים זה מול זה.**

**המקרה הראשון – שני אלמנטים מקוננים:**

</div>

```html
<div class="a">
  <p class="b">אני בתוך a</p>
</div>

```

```css
.a .b { color: red; }    /* ✅ עובד – רווח = "בתוך" */
.a.b  { color: red; }    /* ❌ לא עובד – אין אלמנט עם שתיהן */
```

<div dir="rtl" align="right">

**המקרה השני – אלמנט אחד עם שתי מחלקות:**

</div>

```html
<div class="a b">אני עם שתי המחלקות</div>
```

```css
.a.b  { color: red; }    /* ✅ עובד – בלי רווח = אותו אלמנט */
.a .b { color: red; }    /* ❌ לא עובד – אין כלום בתוכו */
```

<div dir="rtl" align="right">

**הכלל בשורה אחת:**

> **רווח ב-CSS אינו עיצוב טקסט – הוא אופרטור. הוא אומר "בתוך".**

**איך לקרוא סלקטור בקול (בעברית, מימין לשמאל בלוגיקה):**

| הסלקטור | הקריאה |
|----------|---------|
| `.a .b` | "אלמנט b **שנמצא בתוך** אלמנט a" |
| `.a.b` | "אלמנט אחד **שהוא גם** a **וגם** b" |
| `p.intro` | "פסקה **שהיא גם** intro" |
| `.card p` | "פסקה **בתוך** כרטיס" |

### 🌍 מהעולם האמיתי – למה זה כל כך שכיח

מקור הבלבול הוא ה-HTML עצמו. שם, מחלקות מופרדות **ברווח**:

</div>

```html
<div class="card featured">   <!-- כאן רווח = "וגם" -->
```

```css
.card.featured { }            /* אבל כאן חייבים בלי רווח */
```

<div dir="rtl" align="right">

**הרווח אומר "וגם" ב-HTML, ו"בתוך" ב-CSS.** שתי שפות, אותו תו,
משמעות הפוכה. זו לא טעות שלכם – זו מלכודת אמיתית בשפה.

**איך לאבחן בעצמכם ב-10 שניות:**

1. F12 → לחצו על האלמנט שלא נצבע.
2. לשונית **Styles**.
3. **הכלל שלכם לא מופיע שם בכלל?** → הסלקטור **לא תופס** את האלמנט.
   כנראה רווח מיותר או חסר.
4. **הכלל מופיע אבל ~~מחוק בקו~~?** → הוא תופס, אבל **הפסיד בספציפיות**.

**שתי בעיות שונות לחלוטין, עם פתרונות שונים לחלוטין.**
ההבחנה הזו תחסוך לכם שעות.

### ✋ תרגול מיידי

לכל HTML, איזה סלקטור יצבע את הטקסט?

</div>

```html
<!-- א -->
<div class="box warning">טקסט 1</div>

<!-- ב -->
<div class="box"><span class="warning">טקסט 2</span></div>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| ה-HTML | הסלקטור הנכון | למה |
|---------|----------------|------|
| **א** | `.box.warning` | אלמנט **אחד** עם שתי המחלקות |
| **ב** | `.box .warning` | `.warning` נמצא **בתוך** `.box` |

**ומה יקרה אם נתבלבל?**

| הניסיון | על א | על ב |
|----------|-------|-------|
| `.box.warning` | ✅ עובד | ❌ לא – אין אלמנט אחד עם שתיהן |
| `.box .warning` | ❌ לא – אין צאצא | ✅ עובד |

**ואיך כותבים סלקטור שיתפוס את שניהם?** משתמשים בפסיק:

</div>

```css
.box.warning, .box .warning { color: red; }
```

<div dir="rtl" align="right">

או, בכתיב מודרני יותר:

</div>

```css
.box:is(.warning, :has(.warning)) { }   /* מתקדם – נלמד במודול 9 */
```

## 6. סלקטורים של יחסים (משלבים)

### 📖 ההסבר

</div>

```css
/* צאצא (Descendant) – כל a בתוך nav, בכל עומק */
nav a { color: white; }

/* ילד ישיר (Child) – רק li שהם ילדים ישירים של ul */
ul > li { list-style: square; }

/* אח סמוך (Adjacent sibling) – ה-p שבא מיד אחרי h2 */
h2 + p { font-weight: bold; }

/* כל האחים שאחרי (General sibling) – כל p שאחרי h2 */
h2 ~ p { color: gray; }
```

<div dir="rtl" align="right">

</div>

```html
<div class="container">
  <p>א</p>                     ← .container > p   ✅   .container p  ✅
  <h2>כותרת</h2>
  <p>ב</p>                     ← h2 + p           ✅
  <p>ג</p>                     ← h2 + p           ❌ (רק הראשון)
                                 h2 ~ p           ✅ (כל האחים)
  <div class="box">
    <p>ד</p>                   ← .container > p   ❌ (לא ילד ישיר)
  </div>                         .container p     ✅ (כן צאצא)
</div>

```

<div dir="rtl" align="right">

### 🌍 מהעולם האמיתי

**כל אחד מארבעת המשלבים פותר בעיה אמיתית וספציפית:**

**1. `>` – רק הרמה הראשונה.** תפריט עם תת-תפריטים:

</div>

```css
/* רק פריטי התפריט הראשי – לא הפריטים בתוך התת-תפריטים */
.menu > li { border-bottom: 2px solid blue; }
```

<div dir="rtl" align="right">

בלי ה-`>`, גם הפריטים בתוך התת-תפריט הנפתח היו מקבלים קו כחול.

**2. `+` – "האלמנט שבא מיד אחרי".** הפתרון הקלאסי לבעיית המרווחים:

</div>

```css
/* מרווח בין פסקאות – אבל לא לפני הראשונה */
p + p { margin-top: 1em; }
```

<div dir="rtl" align="right">

זה טריק מוכר: במקום לתת `margin-top` לכל פסקה (ואז לבטל אותו לראשונה),
נותנים אותו רק לפסקה שבאה **אחרי** פסקה אחרת. הראשונה לא מושפעת בכלל.

**3. `~` – "כל האחים שאחרי".** בשילוב עם `:checked`, זה מאפשר
אינטראקטיביות **בלי JavaScript**:

</div>

```css
/* כשהצ׳קבוקס מסומן – הראה את התפריט שאחריו */
#menu-toggle:checked ~ .menu { display: block; }
```

<div dir="rtl" align="right">

זהו "טריק הצ׳קבוקס" – איך בונים תפריט המבורגר בלי שורת JS.

**4. רווח (צאצא) – הנפוץ ביותר, וגם הכי מסוכן.**

</div>

```css
.card p { color: gray; }   /* כל פסקה בכרטיס, בכל עומק */
```

<div dir="rtl" align="right">

הוא נוח – אבל הוא תופס **הכול**. אם מחר תוסיפו לכרטיס רכיב מקונן
עם פסקאות משלו, גם הן ייצבעו באפור בלי שהתכוונתם. זו הסיבה
שסלקטורים ממוקדים (מחלקה ייעודית) עדיפים בפרויקטים גדולים.

### ✋ תרגול מיידי

לפי ה-HTML למעלה, אילו פסקאות ייצבעו?

1. `.container > p`
2. `h2 + p`
3. `h2 ~ p`
4. `.container p`

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| הסלקטור | הפסקאות | ההסבר |
|----------|-----------|--------|
| `.container > p` | **א, ב, ג** | ילדים ישירים בלבד. **ד** נמצאת בתוך `.box`. |
| `h2 + p` | **ב בלבד** | `+` תופס **אח סמוך אחד**. ג היא האח השני. |
| `h2 ~ p` | **ב, ג** | כל האחים שאחרי, באותה רמה. א היא **לפני** ה-h2. |
| `.container p` | **א, ב, ג, ד** | כל צאצא בכל עומק. |

**שלוש נקודות שהכי מפספסים:**

1. **`+` תופס אחד בלבד.** לא "כל מה שאחרי" – רק הראשון.
2. **`~` לא תופס לאחור.** פסקה א נמצאת לפני ה-`h2`, ולכן אף פעם
   לא תיתפס. אין ב-CSS "האח הקודם".
3. **`>` מול רווח** – ההבדל היחיד הוא ד.

</div>
</details>

<div dir="rtl" align="right">

## 7. סלקטורים של תכונות

### 📖 ההסבר

</div>

```css
a[target]              { }  /* יש תכונת target */
a[target="_blank"]     { }  /* target שווה בדיוק */
a[href^="https"]       { }  /* מתחיל ב-  (^) */
a[href$=".pdf"]        { }  /* מסתיים ב- ($) */
a[href*="example"]     { }  /* מכיל     (*) */
input[type="email"]    { }  /* שימושי מאוד בטפסים */
```

<div dir="rtl" align="right">

**איך לזכור את שלושת הסימנים:**

| הסימן | המשמעות | דרך זיכרון |
|--------|-----------|-------------|
| `^=` | מתחיל ב- | `^` = "למעלה/התחלה" (כמו regex) |
| `$=` | מסתיים ב- | `$` = "סוף" (כמו regex) |
| `*=` | מכיל | `*` = "כוכבית = הכול" |

### 🌍 מהעולם האמיתי

**זה כלי מקצועי אמיתי שחוסך מחלקות ידניות.**

**הדוגמה הקלאסית – סימון אוטומטי של קישורים:**

</div>

```css
/* קישור חיצוני – חץ יוצא */
a[href^="http"]:not([href*="mysite.co.il"])::after {
  content: " ↗";
}

/* קובץ PDF – סימון סוג הקובץ */
a[href$=".pdf"]::after { content: " (PDF)"; }

/* קישור מייל */
a[href^="mailto:"]::before { content: "✉ "; }

/* קישור טלפון */
a[href^="tel:"]::before { content: "☎ "; }
```

<div dir="rtl" align="right">

**למה זה כל כך שימושי?** בלי זה, כל פעם שמישהו מוסיף קישור ל-PDF
באתר, הוא צריך לזכור להוסיף ידנית `class="pdf-link"`. עם סלקטור
תכונות – **זה קורה מעצמו**, לנצח, גם בתוכן שעורך תוכן יוסיף בעוד שנתיים.

**זו גם דרישת נגישות:** התקן ממליץ להודיע למשתמש כשקישור פותח קובץ
או יוצא מהאתר. כאן זה קורה אוטומטית.

**שימוש שני – עיצוב טפסים לפי סוג:**

</div>

```css
input[type="text"],
input[type="email"],
input[type="tel"] {
  border: 1px solid #ccc;
  padding: 8px;
}

input[type="checkbox"],
input[type="radio"] {
  width: auto;                    /* לא לתת להם רוחב מלא */
}

input[required] { border-inline-start: 3px solid orange; }
input[disabled] { background: #eee; cursor: not-allowed; }
```

<div dir="rtl" align="right">

שימו לב ל-`input[required]` – **סימון ויזואלי אוטומטי של שדות חובה**,
בלי לגעת ב-HTML.

**שימוש שלישי – ניפוי באגים.** הטריק הזה מפורסם:

</div>

```css
/* מסמן באדום כל תמונה בלי alt – כלי בדיקה מהיר */
img:not([alt]) { outline: 3px solid red; }

/* מסמן כל קישור בלי href */
a:not([href]) { outline: 3px solid orange; }
```

<div dir="rtl" align="right">

הדביקו את זה בקונסול של כל אתר ותראו את בעיות הנגישות מיד.

### ✋ תרגול מיידי

כתבו סלקטור לכל מטרה:

1. כל קישור שנפתח בלשונית חדשה
2. כל קישור לקובץ תמונה `.jpg`
3. כל שדה סיסמה
4. כל קישור שה-URL שלו מכיל את המילה `blog`

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```css
a[target="_blank"]     { }   /* 1 – התאמה מדויקת */
a[href$=".jpg"]        { }   /* 2 – מסתיים ב- */
input[type="password"] { }   /* 3 – התאמה מדויקת */
a[href*="blog"]        { }   /* 4 – מכיל */
```

<div dir="rtl" align="right">

**שיפור לשאלה 2 – תמונות מגיעות בכמה פורמטים:**

</div>

```css
a[href$=".jpg"],
a[href$=".jpeg"],
a[href$=".png"],
a[href$=".webp"] { }
```

<div dir="rtl" align="right">

**ובכתיב מודרני, עם `:is()`:**

</div>

```css
a:is([href$=".jpg"], [href$=".png"], [href$=".webp"]) { }
```

<div dir="rtl" align="right">

**טיפ שכדאי להכיר:** אפשר להוסיף `i` להתעלמות מאותיות גדולות/קטנות –
`a[href$=".PDF" i]` יתפוס גם `.pdf` וגם `.PDF`. שימושי מאוד,
כי שמות קבצים לא עקביים.

</div>
</details>

## 8. פסאודו-מחלקות (Pseudo-classes)

### 📖 ההסבר

מתארות **מצב** של אלמנט. נכתבות בנקודתיים אחת `:`.

</div>

```css
/* מצבי עכבר ומקלדת */
a:hover        { color: red; }      /* ריחוף עכבר */
a:active       { color: orange; }   /* בזמן הלחיצה */
a:focus        { outline: 2px solid blue; }  /* מיקוד */
a:focus-visible{ outline: 2px solid blue; }  /* מיקוד ממקלדת בלבד */
a:visited      { color: purple; }   /* קישור שביקרו בו */

/* מיקום ברשימה */
li:first-child  { font-weight: bold; }
li:last-child   { border: none; }
li:nth-child(2) { color: red; }      /* השני */
li:nth-child(odd)  { background: #eee; }  /* אי-זוגיים */
li:nth-child(even) { background: #fff; }  /* זוגיים */
li:nth-child(3n)   { color: blue; }  /* כל שלישי */

/* טפסים */
input:checked   { }
input:disabled  { }
input:required  { }
input:valid     { border-color: green; }
input:invalid   { border-color: red; }
input:placeholder-shown { }

/* שלילה */
li:not(.active) { opacity: 0.5; }

/* אחר */
p:empty { display: none; }
```

<div dir="rtl" align="right">

> ⚠️ **סדר קריטי לקישורים:** `:link` → `:visited` → `:hover` → `:active`.
> ראשי תיבות לזכירה: **LoVe HAte**.

### 🌍 מהעולם האמיתי

**למה סדר ה-LoVe HAte משנה?** כי לכולם **אותה ספציפיות** (0,0,1,1).
כשהספציפיות שווה, מנצח האחרון. אם `:hover` נכתב **לפני** `:visited`,
אז בקישור שביקרתם בו, `:visited` יגבר וה-hover פשוט לא יעבוד.

</div>

```css
/* ❌ שגוי – ה-hover "נבלע" בקישורים שביקרו בהם */
a:hover   { color: red; }
a:visited { color: purple; }

/* ✅ נכון */
a:link    { color: blue; }
a:visited { color: purple; }
a:hover   { color: red; }
a:active  { color: orange; }
```

<div dir="rtl" align="right">

**`:focus` מול `:focus-visible` – ההבדל שמשפר חוויה.**

`:focus` מופעל **בכל** מיקוד – גם בלחיצת עכבר. התוצאה: מסגרת כחולה
מופיעה סביב כל כפתור שלוחצים עליו, וזה נראה "מלוכלך".

התגובה הנפוצה של מפתחים הייתה:

</div>

```css
*:focus { outline: none; }   /* ❌❌ אסון נגישות */
```

<div dir="rtl" align="right">

**וזה הרס את הנגישות של חצי מהאינטרנט.** משתמש מקלדת מאבד לחלוטין
את היכולת לדעת איפה הוא נמצא בדף. נסו: לחצו Tab באתר עם השורה הזו –
אתם "עיוורים".

**`:focus-visible` פותר בדיוק את זה:** הדפדפן מחליט בעצמו.
מיקוד מהמקלדת → מסגרת. לחיצת עכבר → אין מסגרת.

</div>

```css
/* ✅ הדרך הנכונה */
button:focus-visible {
  outline: 3px solid #0d6efd;
  outline-offset: 2px;
}
```

<div dir="rtl" align="right">

**`:nth-child()` – איך לקרוא את הנוסחה `an+b`:**

| הביטוי | מה תופס |
|---------|----------|
| `:nth-child(3)` | השלישי בדיוק |
| `:nth-child(odd)` | 1, 3, 5, 7... |
| `:nth-child(even)` | 2, 4, 6, 8... |
| `:nth-child(3n)` | כל שלישי: 3, 6, 9 |
| `:nth-child(3n+1)` | 1, 4, 7, 10 |
| `:nth-child(-n+3)` | שלושת הראשונים |
| `:nth-last-child(2)` | השני מהסוף |

**השימוש הנפוץ ביותר – פסי זברה בטבלה:**

</div>

```css
tbody tr:nth-child(even) { background: #f7f7f7; }
```

<div dir="rtl" align="right">

זה הופך טבלה של 30 שורות מקיר של מספרים למשהו שהעין יכולה לעקוב אחריו.
תראו את זה בכל דוח, כל גיליון, כל טבלת נתונים מקצועית.

### ⚠️ `:hover` בנייד

אין עכבר בנייד. `:hover` שם מתנהג באופן בלתי צפוי – בדרך כלל הוא
"נדבק" אחרי נגיעה ראשונה, ומשתחרר רק בנגיעה במקום אחר.

**המשמעות המעשית:** תפריט נפתח שמבוסס רק על `:hover` **לא עובד בטלפון**.
אם המשתמש צריך את המידע – הוא חייב להיות נגיש גם בלי ריחוף.

> **כלל:** `:hover` הוא **שיפור**, לא מנגנון. לעולם אל תסתירו
> מידע חיוני או פעולה חיונית מאחוריו בלבד.

### ✋ תרגול מיידי

כתבו סלקטור לכל מטרה:

1. השורות הזוגיות בטבלה
2. כל פריט ברשימה חוץ מהאחרון
3. שדה טופס לא תקין
4. כל פריט שלישי בגלריה

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```css
tr:nth-child(even)        { background: #f5f5f5; }   /* 1 */
li:not(:last-child)       { border-bottom: 1px solid #ddd; }  /* 2 */
input:invalid             { border-color: red; }     /* 3 */
.gallery-item:nth-child(3n) { margin-inline-end: 0; } /* 4 */
```

<div dir="rtl" align="right">

**למה 2 הוא הפתרון האלגנטי:** האלטרנטיבה היא לתת קו לכולם ואז לבטל:

</div>

```css
/* דרך ישנה – שני כללים */
li { border-bottom: 1px solid #ddd; }
li:last-child { border-bottom: none; }

/* דרך מודרנית – כלל אחד */
li:not(:last-child) { border-bottom: 1px solid #ddd; }
```

<div dir="rtl" align="right">

**היתרון האמיתי:** אם מחר יוסיפו פריטים לרשימה, הכל עדיין נכון
**אוטומטית**. וגם – אין צורך במחלקת עזר כמו `.no-border` ב-HTML.

**נקודה על 3:** `:invalid` מופעל **גם על שדה ריק** שהוא `required`,
עוד לפני שהמשתמש נגע בו. זה נראה "אגרסיבי" – הטופס אדום מרגע הטעינה.
הפתרון המקובל:

</div>

```css
/* אדום רק אחרי שהמשתמש עזב את השדה והוא לא ריק */
input:invalid:not(:placeholder-shown) { border-color: red; }
```

</details>

<div dir="rtl" align="right">

## 9. פסאודו-אלמנטים (Pseudo-elements)

### 📖 ההסבר

יוצרים תוכן **וירטואלי**. נכתבים בשתי נקודתיים `::`.

</div>

```css
/* תוכן לפני ואחרי */
.required::after   { content: " *"; color: red; }
.quote::before     { content: "« "; }

/* חלקים באלמנט */
p::first-line      { font-weight: bold; }
p::first-letter    { font-size: 3em; float: right; }
::selection        { background: yellow; }  /* טקסט מסומן */
input::placeholder { color: #999; }
```

<div dir="rtl" align="right">

> ⚠️ ל-`::before` ו-`::after` **חובה** מאפיין `content`, אפילו ריק
> (`content: "";`). בלעדיו הם לא יופיעו כלל.

| | פסאודו-מחלקה `:` | פסאודו-אלמנט `::` |
|---|-------------------|--------------------|
| מתארת | **מצב** של אלמנט קיים | **חלק וירטואלי** חדש |
| דוגמאות | `:hover` `:first-child` | `::before` `::first-letter` |
| ספציפיות | כמו מחלקה (0,0,1,0) | כמו תגית (0,0,0,1) |

### 🌍 מהעולם האמיתי

**איפה `::before` ו-`::after` מופיעים באתרים אמיתיים:**

</div>

```css
/* 1. כוכבית אדומה בשדות חובה – בלי לגעת ב-HTML */
label.required::after { content: " *"; color: red; }

/* 2. אייקון לפני קישור */
.link-external::after { content: " ↗"; }

/* 3. מפריד בין פירורי לחם */
.breadcrumb li:not(:first-child)::before { content: " / "; color: #999; }

/* 4. "ניקוי" צף – טכניקה קלאסית */
.clearfix::after { content: ""; display: block; clear: both; }

/* 5. אות ראשונה מוגדלת, כמו בספר */
article > p:first-of-type::first-letter {
  font-size: 3em;
  float: right;      /* בעברית: ימין */
  line-height: 1;
  padding-inline-start: 8px;
}
```

<div dir="rtl" align="right">

**דוגמה 3 היא הכי מלמדת.** בלי `::before`, כל פירור לחם היה צריך
`<span> / </span>` ידני ב-HTML – ומישהו היה צריך לזכור **לא** לשים
אותו לפני הראשון. עם CSS, זה עובד לנצח, על כל מספר פריטים.

**♿ נגישות – האזהרה החשובה:**

> תוכן שנוצר ב-`content` **אינו טקסט אמיתי** בדף. הוא לא נבחר בעכבר,
> לא נמצא ב-`Ctrl+F`, ולא נכנס להעתקה. חלק מקוראי המסך מקריאים אותו
> וחלק לא – ההתנהגות **אינה עקבית**.
>
> **המסקנה: לעולם אל תשימו שם מידע חיוני.**

</div>

```css
/* ❌ מסוכן – אם קורא המסך לא יקריא, המשתמש לא ידע */
.price::before { content: "מחיר: "; }

/* ✅ בטוח – דקורטיבי בלבד, המידע כבר קיים */
.external::after { content: " ↗"; }
```

<div dir="rtl" align="right">

**מגבלה שחשוב להכיר:** `::before` ו-`::after` **לא עובדים** על
אלמנטים ריקים (void) – `<img>`, `<input>`, `<br>`, `<hr>`.
למה? כי הם מוסיפים תוכן **בתוך** האלמנט, ולאלמנטים האלה אין "בפנים".

זו הסיבה שאי אפשר לשים אייקון על `<input>` עם `::before` –
צריך לעטוף אותו ב-`<div>` ולשים על העטיפה.

### ✋ תרגול מיידי

1. הוסיפו " ←" אחרי כל קישור עם `class="more"`.
2. הוסיפו קו מפריד " | " בין פריטי רשימה, חוץ מהאחרון.

</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

```css
/* 1 */
a.more::after {
  content: " ←";
  color: #0d6efd;
}

/* 2 */
.nav-list li:not(:last-child)::after {
  content: " | ";
  color: #ccc;
  margin: 0 6px;
}
```

<div dir="rtl" align="right">

**שלוש נקודות:**

1. **`::after` ולא `::before`** בשאלה 2 – המפריד בא **אחרי** הפריט.
   (אפשר גם `::before` על `:not(:first-child)` – תוצאה זהה.)
2. **`:not(:last-child)`** מונע מפריד מיותר בסוף.
3. **`content` הוא היחיד שחובה.** בלעדיו – שום דבר לא יופיע,
   ולא תהיה שום הודעת שגיאה.

**המלכודת הנפוצה:** לשכוח את המרכאות. `content: ←` אינו תקין;
חייב `content: " ←"`.

</div>
</details>

<div dir="rtl" align="right">

## 10. ספציפיות (Specificity) – החלק הכי חשוב

### 📖 ההסבר

**השאלה:** כשכמה כללים פונים לאותו אלמנט – מי מנצח?
**התשובה:** מי שיותר **ספציפי**.

### שיטת החישוב

לכל סלקטור מחשבים ניקוד בן 4 ספרות: `(inline, id, class, element)`

| רכיב | ניקוד |
|-------|--------|
| `style=""` inline | 1,0,0,0 |
| `#id` | 0,1,0,0 |
| `.class`, `[attr]`, `:hover` | 0,0,1,0 |
| תגית, `::before` | 0,0,0,1 |
| `*`, `:not()` עצמו | 0,0,0,0 |

### דוגמאות

| סלקטור | חישוב | ניקוד |
|---------|--------|--------|
| `p` | תגית אחת | 0,0,0,1 |
| `.intro` | מחלקה אחת | 0,0,1,0 |
| `p.intro` | תגית + מחלקה | 0,0,1,1 |
| `#main` | מזהה אחד | 0,1,0,0 |
| `#main p` | מזהה + תגית | 0,1,0,1 |
| `nav ul li a` | 4 תגיות | 0,0,0,4 |
| `.nav .item a` | 2 מחלקות + תגית | 0,0,2,1 |
| `a[href^="https"]` | תגית + תכונה | 0,0,1,1 |
| `li:not(.active)` | תגית + מחלקה (בתוך not) | 0,0,1,1 |
| `style="..."` | inline | 1,0,0,0 |

### 🔨 שלב אחר שלב – הטעות שכולם עושים

**הניקוד אינו מספר אחד. הוא ארבע עמודות נפרדות.**

**שלב 1 – השאלה:** מי מנצח?

</div>

```css
#sidebar        { color: blue; }    /* (0,1,0,0) */
.a .b .c .d .e  { color: red; }     /* (0,0,5,0) */
```

<div dir="rtl" align="right">

**שלב 2 – התשובה האינטואיטיבית (והשגויה):** "5 מחלקות מול מזהה אחד,
אז 5 > 1, האדום מנצח."

**שלב 3 – מה באמת קורה.** ההשוואה היא **עמודה-עמודה, משמאל לימין**,
והיא **עוצרת ברגע שיש הכרעה**:

</div>

```
        inline   id    class   element
        ------  ----   -----   -------
כחול      0      1       0        0
אדום      0      0       5        0
        ------  ----   -----   -------
עמודה 1:  0  =  0    → תיקו, ממשיכים
עמודה 2:  1  >  0    → הכרעה! עוצרים כאן.
```

<div dir="rtl" align="right">

**שלב 4 – התוצאה: כחול.** העמודה של המחלקות **מעולם לא נבדקה**.

**האנלוגיה שמסבירה הכול:** זה כמו להשוות מספרים לפי ספרות.
`1,000` מול `0,999` – האלף מנצח. אף אחד לא סוכם `0+9+9+9=27` ומשווה
ל-`1+0+0+0=1`. **אותו דבר בדיוק בספציפיות.**

**ולכן:** אפילו `.a.b.c.d.e.f.g.h.i.j.k` (11 מחלקות) **מפסיד** ל-`#x`.

### ⚠️ `!important` – נשק יום הדין

</div>

```css
p { color: blue !important; }  /* גובר כמעט על הכול */
```

<div dir="rtl" align="right">

**זו לא "ספציפיות גבוהה" – זו יציאה מהמערכת.** `!important` מקפיץ
את הכלל לשכבה נפרדת לגמרי, שמעל כל הספציפיות.

**למה זו בעיה כל כך גדולה:**

| הבעיה | ההסבר |
|--------|--------|
| **שובר את הכלי** | מרגע שיש `!important` בקוד, אי אפשר יותר **לחשב** מי ינצח. צריך לחפש. |
| **מדבק** | הדרך היחידה לגבור על `!important` היא `!important` אחר. תוך חודשיים כל הקובץ מלא בהם. |
| **מסתיר את הבעיה** | הצורך בו הוא כמעט תמיד סימפטום לסלקטורים ספציפיים מדי (בדרך כלל `id`) במקום אחר. |

**מתי כן מותר:**

| המקרה | ההסבר |
|--------|--------|
| דריסת ספרייה חיצונית | אין לכם גישה לקוד של Bootstrap |
| מחלקת עזר חד-משמעית | `.hidden { display: none !important; }` |
| דריסת `style=""` מ-JS של צד שלישי | המקרה היחיד שאין בו כלי אחר |

**מה לעשות במקום:** להגביר ספציפיות **באופן מבוקר**:

</div>

```css
/* הבעיה: הכלל שלנו מפסיד */
#sidebar .btn { background: gray; }   /* (0,1,1,0) */
.btn-success  { background: green; }  /* (0,0,1,0) ← מפסיד */

/* ❌ הפתרון הרע */
.btn-success  { background: green !important; }

/* ✅ הפתרון הנכון – מעלים ספציפיות באופן טבעי */
#sidebar .btn-success { background: green; }   /* (0,1,2,0) ← מנצח */

/* ✅✅ הפתרון הכי טוב – לא לכתוב #sidebar .btn מלכתחילה */
```

<div dir="rtl" align="right">

### ✋ תרגול מיידי

חשבו ניקוד לכל סלקטור, וקבעו מי מנצח:

</div>

```css
#header .nav a       { color: red; }
.site .nav .link a   { color: blue; }
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| הסלקטור | הפירוק | הניקוד |
|----------|---------|---------|
| `#header .nav a` | 1 מזהה + 1 מחלקה + 1 תגית | **(0,1,1,1)** |
| `.site .nav .link a` | 3 מחלקות + 1 תגית | **(0,0,3,1)** |

**ההשוואה:**

</div>

```
        inline   id    class   element
אדום      0      1       1        1
כחול      0      0       3        1
                 ↑
              הכרעה כאן
```

<div dir="rtl" align="right">

**אדום מנצח.** עמודת ה-`id`: 1 > 0. ההשוואה עוצרת שם –
העובדה שלכחול יש שלוש מחלקות מול מחלקה אחת **לא נבדקת בכלל**.

**איך לוודא בעצמכם בדפדפן:**
F12 → בחרו את הקישור → לשונית **Styles**.
תראו את שני הכללים, כשהמפסיד מופיע ~~עם קו חוצה~~.
כרום אפילו ממיין אותם לפי ספציפיות – החזק למעלה.

</div>
</details>

<div dir="rtl" align="right">

## 11. ירושה (Inheritance)

### 📖 ההסבר

חלק מהמאפיינים עוברים אוטומטית מהורה לילדים.

</div>

```css
body {
  font-family: Arial;
  color: #333;
}
/* כל האלמנטים בדף יירשו את הפונט והצבע */
```

<div dir="rtl" align="right">

| ✅ עוברים בירושה | ❌ לא עוברים בירושה |
|-------------------|---------------------|
| `color` | `margin` `padding` |
| `font-family` `font-size` `font-weight` | `border` |
| `line-height` | `background` |
| `text-align` | `width` `height` |
| `direction` | `display` `position` |
| `visibility` `cursor` | |

### 🌍 מהעולם האמיתי

**יש היגיון מלא מאחורי החלוקה הזו – היא לא שרירותית.**

| הקבוצה | מה עובר | למה |
|---------|----------|------|
| **תכונות טקסט** | `color`, `font-*`, `line-height`, `direction` | טקסט **זורם** דרך אלמנטים מקוננים. הגיוני שפסקה בתוך div תשמור על אותו פונט. |
| **תכונות קופסה** | `margin`, `padding`, `border`, `width` | **מזעזע** אילו עברו. `border: 1px` על `<body>` היה נותן מסגרת לכל אלמנט בדף. |

**זה מה שמאפשר את הדפוס הנפוץ ביותר בכל פרויקט CSS:**

</div>

```css
body {
  font-family: 'Assistant', Arial, sans-serif;
  font-size: 16px;
  line-height: 1.6;
  color: #212529;
  direction: rtl;
}
```

<div dir="rtl" align="right">

**חמש שורות – וכל הדף מעוצב.** בלי ירושה, הייתם צריכים לכתוב את זה
לכל תגית בנפרד.

**⚠️ הנקודה הכי חשובה בסעיף: ערך שהתקבל בירושה הוא החלש ביותר בעולם.**

</div>

```css
body { color: navy; }     /* p יירש navy */
* { color: black; }       /* (0,0,0,0) – ובכל זאת מנצח! */
```

<div dir="rtl" align="right">

**למה?** כי ערך תורשתי **אינו כלל שחל על האלמנט**. הוא ערך שהגיע מלמעלה
בהיעדר כלל. ברגע שקיים **כל כלל שהוא** על האלמנט עצמו – אפילו בניקוד
(0,0,0,0) – הוא גובר.

**זו הסיבה ש-`* { color: black }` הוא רעיון רע:** הוא שובר ירושה
בכל הדף, ואז כל שינוי צבע דורש כלל מפורש לכל אלמנט.

**המילים המיוחדות – שליטה ידנית בירושה:**

</div>

```css
.child {
  color: inherit;  /* קח מההורה בכוח, גם אם לא יורש כרגיל */
  border: initial; /* חזור לברירת המחדל של הדפדפן */
  margin: unset;   /* inherit אם יורש, אחרת initial */
  padding: revert; /* חזור לברירת המחדל של הדפדפן לתגית הזו */
}
```

<div dir="rtl" align="right">

**`inherit` שימושי במיוחד בשני מקרים:**

</div>

```css
/* 1. כפתור לא יורש פונט מהדפדפן – מכריחים אותו */
button, input, select, textarea {
  font: inherit;
}

/* 2. קישור בתוך כותרת שלא יהיה כחול */
h2 a { color: inherit; }
```

<div dir="rtl" align="right">

**המקרה הראשון הוא כלל שכל פרויקט צריך.** אלמנטי טופס מקבלים
פונט מערכת מהדפדפן ולא יורשים מ-`body` – ולכן בלי השורה הזו,
כל כפתור באתר יראה בפונט אחר מהטקסט סביבו.

### ✋ תרגול מיידי

איזה צבע וגודל יהיו לפסקה?

</div>

```css
body { color: navy; font-size: 18px; border: 2px solid red; }
div  { font-size: 20px; }
```

```html
<body>
  <div>
    <p>איזה צבע? איזה גודל? יש לי מסגרת?</p>
  </div>
</body>
```

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

| המאפיין | הערך | ההסבר |
|----------|-------|--------|
| `color` | **navy** | עובר בירושה מ-`body` → `div` → `p`. ירושה עוברת דרך **כל** הרמות. |
| `font-size` | **20px** | גם עובר בירושה, אבל ה-`div` **דרס** אותו בדרך. הפסקה יורשת מההורה **הישיר** שלה. |
| `border` | **אין** | `border` **אינו** תכונה תורשתית. רק ל-`<body>` יש מסגרת אדומה. |

**התובנה המרכזית:** ירושה עוברת שרשרת, וכל חוליה יכולה לשנות את הערך
עבור כל מה שמתחתיה. `p` לא "מסתכל על `body`" – הוא מקבל את מה
שההורה שלו החזיק באותו רגע.

**איך לראות את זה בדפדפן:** F12 → בחרו את ה-`<p>` → לשונית **Computed**.
חפשו `color`. תראו את הערך הסופי, ולידו מאיזה כלל הוא הגיע.
כרום כותב במפורש "Inherited from div".

</div>
</details>

<div dir="rtl" align="right">

## 12. המפל (The Cascade) – סדר ההכרעה

### 📖 ההסבר

כשיש התנגשות, הדפדפן מכריע לפי הסדר הבא, **ועוצר ברגע שיש הכרעה**:

| # | הקריטריון | הדוגמה |
|---|------------|---------|
| **0** | האם הסלקטור בכלל תופס? | אם לא – אין תחרות |
| **1** | `!important` | כלל עם important גובר על כל כלל רגיל |
| **2** | **ספציפיות** | (0,1,0,0) > (0,0,9,9) |
| **3** | **סדר הופעה** | האחרון בקוד מנצח |
| **4** | ירושה מההורה | אם אין שום כלל |
| **5** | ברירת המחדל של הדפדפן | `<h1>` גדול ומודגש כברירת מחדל |

### 🌍 מהעולם האמיתי – שיטת האבחון בשלושה צעדים

**כשכלל CSS "לא עובד", התשובה תמיד באחד משלושת המקומות האלה.
עברו עליהם לפי הסדר:**

**צעד 1 – האם הסלקטור בכלל תופס?**

F12 → לחצו על האלמנט → לשונית **Styles**.
**הכלל שלכם לא מופיע ברשימה בכלל?** הסלקטור לא תופס.

הסיבות השכיחות:
- רווח מיותר או חסר (`.a .b` מול `.a.b`)
- שגיאת כתיב במחלקה
- שכחתם נקודה או סולמית
- ה-`<link>` לא נטען (בדקו בלשונית Network – 404?)

**צעד 2 – הכלל מופיע אבל ~~מחוק בקו~~?**

הוא תופס, אבל **הפסיד**. הסתכלו איזה כלל למעלה ממנו ניצח, וחשבו
את הספציפיות של שניהם.

הפתרון: להגביר את הספציפיות של הכלל שלכם – **לא** `!important`.

**צעד 3 – הכלל מופיע ולא מחוק, ועדיין לא רואים כלום?**

אז הבעיה אינה במפל. אולי:
- האלמנט מוסתר (`display: none`, `opacity: 0`, מאחורי אלמנט אחר)
- הערך לא חוקי (`color: bluu`) – הדפדפן מתעלם בשקט
- המאפיין לא חל על סוג האלמנט (`width` על `<span>` – ראו מודול 8 ב-HTML)

> 💡 **הלשונית Computed** מראה את הערך **הסופי** שהדפדפן חישב,
> אחרי כל ההכרעות. אם שם רשום משהו אחר ממה שציפיתם – עקבו אחורה.

## 📋 סיכום – טבלת הסלקטורים

| סלקטור | בוחר | ספציפיות |
|---------|-------|-----------|
| `p` | כל תגיות p | 0,0,0,1 |
| `.cls` | כל אלמנט עם המחלקה | 0,0,1,0 |
| `#id` | האלמנט עם המזהה | 0,1,0,0 |
| `*` | הכול | 0,0,0,0 |
| `a, b` | גם a וגם b | לכל אחד בנפרד |
| `a b` | b **בתוך** a (כל עומק) | סכום |
| `a > b` | b שהוא **ילד ישיר** של a | סכום |
| `a + b` | b שבא **מיד אחרי** a | סכום |
| `a ~ b` | **כל** b שאחרי a | סכום |
| `[attr]` | לפי תכונה | 0,0,1,0 |
| `:hover` | מצב | 0,0,1,0 |
| `::before` | חלק וירטואלי | 0,0,0,1 |
| `:not(x)` | כל מה שאינו x | של x |

### 🎯 שלושת הדברים שחייבים לזכור מהמודול

1. **רווח ב-CSS הוא אופרטור** שאומר "בתוך". `.a .b` ≠ `.a.b`.
2. **ספציפיות היא ארבע עמודות**, לא סכום. משווים משמאל לימין ועוצרים בהכרעה.
3. **F12 → Styles** עונה על "למה זה לא עובד" ב-90% מהמקרים.

### תרגיל 3 – משלבים ותכונות 🟡

**קובץ:** [`exercises/ex3-combinators.html`](exercises/ex3-combinators.html) ·

### תרגיל 4 – ספציפיות: לחשב, לנחש, לתקן 🟡

**קובץ:** [`exercises/ex4-specificity.html`](exercises/ex4-specificity.html) ·
[פתרון](solutions/ex4-specificity.html)

**חלק א׳ – חישוב על הנייר.** לכל סלקטור, כתבו `(inline, id, class, element)`:

</div>

```
1.  p                    6.  #main .card p
2.  .box                 7.  div.card.featured
3.  #header              8.  a[href^="https"]
4.  ul li                9.  ul li a.link
5.  .nav a:hover        10.  *
```

**חלק ב׳ – ניחוש לפני הרצה.** בקובץ 5 מקרי התנגשות. לכל אחד,

אם טעיתם – כתבו למה.

**חלק ג׳ – תיקון.** בסוף הקובץ יש כלל שמפסיד.
**תקנו אותו – בלי `!important` ובלי לגעת ב-HTML.**

**🌍 למה חלק ב׳ בנוי כך:** לנחש לפני שרואים הוא ההבדל בין להבין
לבין לנסות עד שזה עובד. אם אתם יכולים לחזות את התוצאה –
תוכלו גם לאבחן באג בעוד חודש.

### תרגיל 5 – תפריט ניווט מלא ⭐

**קובץ:** [`exercises/ex5-nav-menu.html`](exercises/ex5-nav-menu.html) ·
[פתרון](solutions/ex5-nav-menu.html)

בנו תפריט ניווט אופקי, שכולו מבוסס על **סלקטורים בלבד**.

1. התפריט הוא `<ul>` עם `<li>`-ים – בלי נקודות רשימה.
2. הקישורים בצבע כהה; ב-`:hover` מחליפים צבע **בהדרגה** (`transition`).
3. הקישור הפעיל (`.active`) מודגש ובעל קו תחתון בצבע שונה.
4. בכל פריט חוץ מהאחרון – קו מפריד. השתמשו ב-`:not(:last-child)` –
   **לא** במחלקה נוספת.
5. הפריט הראשון מקבל טיפול מיוחד עם `:first-child`.
6. אייקון "◂" לפני כל פריט – עם `::before`, **לא** ב-HTML.
7. לקישור עם `class="external"` – "↗" עם `::after`.
8. שדה החיפוש: מסגרת משתנה ב-`:focus`, placeholder אפור בהיר.

**מגבלות:**
- ❌ אסור `!important`.
- ❌ אסור להוסיף מחלקות ל-HTML, חוץ מ-`.active` ו-`.external`.
- ✅ מותר וכדאי להשתמש במשתני CSS (`--color-main`).

**🌍 למה זה תרגיל אמיתי:** תפריט ניווט הוא הרכיב שכל אתר בעולם צריך,
וזה הרכיב שבו ההבדל בין קוד טוב לקוד רע הכי בולט. תפריט שנשען על
סלקטורים ממשיך לעבוד כשמוסיפים פריט. תפריט שנשען על מחלקות עזר
(`.first`, `.last`, `.no-border`) נשבר בכל שינוי.
