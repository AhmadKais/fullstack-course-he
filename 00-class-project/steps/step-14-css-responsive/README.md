## 🎯 מה מוסיפים היום

- בודקים את האתר במצב מכשיר נייד ורואים מה נשבר.
- מוסיפים **Media Queries** – שני נקודות שבירה בלבד, לא שבע.
- מתקנים את הכותרת בטלפון, מקטינים כותרות, ומאפשרים לטבלה לגלול לבד.
- מבינים למה `<meta viewport>` היה שם מהשיעור הראשון.

</div>

<div dir="rtl" align="right">

## 🌍 למה זה ככה בעולם האמיתי

### קודם כול – תראו את הבעיה

`F12` ← אייקון הטלפון (`Ctrl+Shift+M`) ← בחרו iPhone SE (375px).

זה **המסך הצר ביותר שעדיין נפוץ**. אם האתר עובד שם, הוא עובד כמעט בכל מקום.
מעל 60% מהתנועה לאתר של בית קפה מגיעה מטלפון – בדרך כלל ממישהו
שעומד ברחוב ומחפש מתי אתם נסגרים.

### השורה שהייתה שם מהשיעור הראשון

</div>

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

<div dir="rtl" align="right">

**בלי השורה הזו כל שאר השיעור הזה חסר משמעות.**

טלפונים מעמידים פנים שהמסך שלהם ברוחב 980px ואז מקטינים את כל הדף –
זה נועד לאתרים מ-2008 שלא ידעו על טלפונים. התוצאה: אתר קריא בזכוכית מגדלת.

`width=device-width` אומר *"תשתמש ברוחב האמיתי"*. רק אז ה-Media Queries מתחילות לפעול.

**נסו:** הסירו את השורה מ-`index.html`, רעננו במצב מכשיר. הכול מתכווץ.

### Mobile First – ולמה `min-width` ולא `max-width`

</div>

```css
/* ברירת מחדל = מסך קטן. אין Media Query. */
.card { padding: 14px; }

/* יש יותר מקום? הוסף. */
@media (min-width: 700px) {
  .card { padding: 24px; }
}
```

<div dir="rtl" align="right">

| הגישה | מה קורה |
|--------|----------|
| **Mobile First** (`min-width`) | הטלפון מקבל את הקוד הפשוט. שיפורים מתווספים |
| Desktop First (`max-width`) | הטלפון מוריד את **כל** הקוד ואז מבטל חצי ממנו |

**היום כותבים Mobile First.** אנחנו נשתמש בשתי הגישות בקובץ שלנו כי חלק מהעיצוב
כבר נכתב לרוחב – זה מצב מציאותי לחלוטין בפרויקט קיים, וזה בסדר.

### כמה נקודות שבירה?

**לא לפי מכשירים.** אין "נקודת שבירה של אייפון" – יש עשרים גדלים של אייפון,
וגם מסכים מפוצלים במחשב.

> **הכלל: מרחיבים את החלון לאט. איפה שזה מתחיל להיראות רע – שם נקודת שבירה.**

אצלנו שתיים: **699px** (מתחת = טלפון) ו-**1000px** (מעל = מסך רחב).
זה מספיק לרוב האתרים.

### מה כבר עובד בלי שנגענו

בזכות שלושה דברים שכתבנו קודם, חצי מהעבודה כבר עשויה:
- `flex-wrap: wrap` – הניווט יורד שורה לבד.
- `auto-fit` + `minmax` – הרשתות הופכות לעמודה אחת לבד.
- `max-width: 100%` על תמונות – שום תמונה לא גולשת.

**CSS מודרני רספונסיבי מלכתחילה.** ה-Media Queries הן ליטוש, לא הפתרון.

</div>

## 🔨 שלב אחר שלב

### 1. הכותרת בטלפון

</div>

```css
@media (max-width: 699px) {
  .site-header {
    flex-direction: column;
    align-items: stretch;
    text-align: center;
    padding: 10px 14px;
  }

  #main-nav ul {
    justify-content: center;
    flex-wrap: wrap;
    gap: 6px 14px;
  }
}
```

<div dir="rtl" align="right">

לוגו למעלה, ניווט מתחתיו וממורכז. `gap: 6px 14px` = 6 בין שורות, 14 בין פריטים.

> **הערה:** תפריט "המבורגר" אמיתי דורש JavaScript כדי לפתוח ולסגור.
> נוסיף אותו ב**שלב 25**. עד אז, ניווט שיורד שורה הוא פתרון תקין לחלוטין
> לארבעה פריטים – והרבה אתרים באמת עושים את זה.

### 2. כותרות קטנות יותר

</div>

```css
@media (max-width: 699px) {
  h1 { font-size: 1.9rem; }
  h2 { font-size: 1.4rem; }
}

@media (min-width: 1000px) {
  h1 { font-size: 3rem; }
}
```

<div dir="rtl" align="right">

`2.5rem` = 40px. במסך 375px זה **עשר אותיות בשורה**. הכותרת נשברת לארבע שורות
ודוחפת את כל התוכן מתחת לקו הקיפול.

בשלב 16 נחליף את שלושת הכללים האלה ב**שורה אחת** עם `clamp()`.

### 3. הטבלה שלא נשברת

</div>

```html
<div class="table-wrap">
  <table>...</table>
</div>
```


```css
@media (max-width: 699px) {
  .table-wrap { overflow-x: auto; }
}
```

<div dir="rtl" align="right">

טבלה עם שלוש עמודות במסך 375px גורמת ל**כל הדף** לגלול לצדדים – וזו
תחושת "אתר שבור" קלאסית.

**הכלל:** תוכן רחב (טבלאות, בלוקי קוד, דיאגרמות) גולל **בתוך המכל שלו**.
הדף עצמו לעולם לא גולל אופקית.

### 4. שדות בטופס

</div>

```css
@media (max-width: 699px) {
  input, select, textarea { max-width: 100%; }
}
```

<div dir="rtl" align="right">

ה-`max-width: 380px` נהדר במחשב, ובמסך 375px הוא משאיר שוליים מוזרים.

> 💡 **טיפ שחוסך תלונות:** בשדה טופס עם `font-size` **קטן מ-16px**,
> ה-iPhone **מזוים אוטומטית** על השדה בלחיצה, והמשתמש נשאר עם דף מוגדל.
> שדות הטופס שלנו יורשים 17px, אז אנחנו מוגנים.

## 💻 מה נוסף ל-`style.css` היום

</div>

```css
/* ============================================================
   שלב 14 · CSS מודול 7 – רספונסיביות
   ============================================================
   כל מה שלמעלה הוא ברירת המחדל = המסך הקטן.
   כאן מוסיפים רק את מה שמשתנה כשיש יותר מקום.            */

/* --- מתחת ל-700px: המסך הקטן --- */
@media (max-width: 699px) {
  .site-header {
    flex-direction: column;
    align-items: stretch;
    text-align: center;
    padding: 10px 14px;
  }

  #main-nav ul {
    justify-content: center;
    flex-wrap: wrap;
    gap: 6px 14px;
  }

  h1 { font-size: 1.9rem; }
  h2 { font-size: 1.4rem; }

  main { padding: 16px 14px 40px; }

  .hero::after { display: none; }   /* אין מקום לתווית על מסך צר */

  /* טבלה שלא נשברת: גלילה אופקית בתוך עצמה */
  .table-wrap {
    overflow-x: auto;
  }

  input, select, textarea { max-width: 100%; }

  .site-footer {
    flex-direction: column;
    align-items: flex-start;
  }
}

/* --- 1000px ומעלה: מסך רחב --- */
@media (min-width: 1000px) {
  h1 { font-size: 3rem; }
}

/* תמונות תמיד נכנסות למכל שלהן */
img,
video {
  height: auto;
}
```

<div dir="rtl" align="right">

## 👀 מה רואים במסך

**במצב מכשיר נייד (375px):**
- הכותרת בשתי שורות ממורכזות – לוגו מעל, ניווט מתחת.
- הכותרות בגודל שמתאים למסך.
- **הטבלה גוללת בפנים** – הדף עצמו לא זז לצדדים.
- הגלריה והתפריט בעמודה אחת.
- התווית "נפתח ב-07:00" נעלמה, כי אין לה מקום.

**במסך רחב:** הכותרת הראשית גדלה ל-3rem.

## ✋ אתגר לכיתה

1. הסתירו את הגלריה כולה במסכים מתחת ל-500px.
2. **בדיקה:** הסירו את `<meta viewport>` מ-`index.html` ובדקו במצב מכשיר. תחזירו.
3. **שאלה:** למה `@media (max-width: 699px)` ולא `700px`?

</div>
</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

**1.**

`@media (max-width: 499px) { .gallery { display: none; } }`

⚠️ אבל **שאלו את עצמכם אם זה נכון**. הסתרה במובייל אומרת שמשתמש הטלפון –
שהוא הרוב – לא רואה את התוכן בכלל. אם התמונות חשובות, עדיף להציג אחת
ולתת "עוד תמונות". אם הן לא חשובות, למה הן בדף בכלל?

**2.** כל האתר מתכווץ לגודל בלתי קריא, וה-Media Queries **לא מופעלות** –
הדפדפן חושב שהוא ברוחב 980px. זו הסיבה שהשורה הזו קיימת מהשיעור הראשון.

**3. כדי שלא יהיה חפיפה.** אם היינו כותבים `max-width: 700px` וגם
`min-width: 700px`, במסך של **בדיוק** 700px **שני** הכללים היו חלים,
והמנצח היה נקבע לפי סדר הכתיבה בקובץ.

`699px` ו-`700px` לא נפגשים לעולם. (מקצוענים משתמשים ב-`699.98px`
בגלל מסכים עם זום שמדווחים על שברי פיקסלים.)

## 🔍 טעויות שראינו בכיתה

| הטעות | מה קורה |
|--------|----------|
| בלי `<meta viewport>` | כל השיעור הזה לא עובד |
| נקודת שבירה לכל דגם טלפון | קובץ בלתי ניתן לתחזוקה |
| `max-width: 700px` וגם `min-width: 700px` | חפיפה בדיוק על הגבול |
| הסתרת תוכן חשוב במובייל | הרוב לא רואה אותו |
| בדיקה רק בהקטנת חלון | חלון צר במחשב ≠ מסך טלפון (אין מגע, יש עכבר) |
