- מחליפים שלוש Media Queries של גודל כותרת ב-**`clamp()`** אחד.

## 🌍 למה זה ככה בעולם האמיתי

### הבעיה: ספרנו את `#4a2c17`

חפשו בקובץ של שלב 15 את `#4a2c17`. הוא מופיע **שבע פעמים**. `#f5efe6` – חמש.

לקוח מבקש להחליף את החום לירוק. עכשיו זה 12 חיפושים-והחלפות, ואם פספסתם
אחד – יש כתם חום באתר ירוק. **זה לא תרחיש היפותטי; זו העבודה.**

### הפתרון: משתנים אמיתיים בדפדפן

</div>

```css
:root {
  --brand-dark: #4a2c17;
}

.site-header { background-color: var(--brand-dark); }
```

<div dir="rtl" align="right">

**זה לא Sass.** משתני CSS **חיים בדפדפן**: הם עוברים בירושה, אפשר לשנות אותם
ב-JavaScript בשורה אחת, ואפשר להחליף אותם ב-Media Query.

זה בדיוק מה שהופך את המצב הכהה לזול.

### מצב כהה בשלושים שורות במקום באלף

</div>

```css
:root {
  --bg: #f5efe6;
  --ink: #2b2b2b;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --bg: #17110c;
    --ink: #efe6da;
  }
}
```

<div dir="rtl" align="right">

**כל הכללים באתר ממשיכים להגיד `var(--bg)`.** לא נגענו באף אחד מהם –
רק בערכים.

בלי משתנים היינו כותבים `@media (prefers-color-scheme: dark)` ואז **משכפלים
כל כלל שיש בו צבע**. עם משתנים זה בלוק אחד.

**המבנה `:root:not([data-theme="light"])`** מאפשר למשתמש **לגבור על המערכת**:
אם הוא בחר מפורשות "בהיר", אנחנו לא כופים כהה גם אם המערכת כהה.
בשלב 29 נוסיף כפתור שכותב את התכונה הזו.

### `clamp()` – שלוש Media Queries בשורה אחת

**במקום:**

</div>

```css
h1 { font-size: 2.5rem; }
@media (max-width: 699px)  { h1 { font-size: 1.9rem; } }
@media (min-width: 1000px) { h1 { font-size: 3rem; } }
```

<div dir="rtl" align="right">

**כותבים:**

</div>

```css
h1 { font-size: clamp(1.9rem, 1.2rem + 3vw, 3rem); }
/*                   מינימום  ערך רצוי    מקסימום */
```

<div dir="rtl" align="right">

הערך האמצעי גדל **ברציפות** עם רוחב המסך, וה-`clamp` לא נותן לו לרדת מתחת
למינימום או לעלות מעל המקסימום. **אין קפיצות** בנקודות שבירה – הגודל זורם.

`1.2rem + 3vw` ולא `3vw` לבד: `vw` נקי מתעלם מהגדרת גודל הגופן של המשתמש
ולא מאפשר להגדיל טקסט בזום. השילוב שומר על שניהם.

### מאפיינים לוגיים – **הפרק שהכי חשוב לאתר בעברית**

</div>

```css
/* פיזי – כתוב לפי כיוון */
margin-left: auto;
border-right: 4px solid;
padding: 0 20px;

/* לוגי – כתוב לפי תפקיד */
margin-inline: auto;
border-inline-start: 4px solid;
padding-inline: 20px;
```

<div dir="rtl" align="right">

| פיזי | לוגי | ב-RTL |
|-------|-------|--------|
| `left` / `right` | `inline-start` / `inline-end` | `start` = **ימין** |
| `top` / `bottom` | `block-start` / `block-end` | ללא שינוי |
| `text-align: right` | `text-align: start` | לפי כיוון המסמך |

**למה זה חשוב דווקא לנו:** הקו הזהוב של הציטוט צריך להיות **בהתחלה** של הטקסט.
בעברית זה ימין, באנגלית שמאל. עם `border-right` נצטרך להפוך את כל הקובץ
כשנוסיף גרסה באנגלית. עם `border-inline-start` – **זה כבר עובד בשתי השפות.**

זו לא תיאוריה: כל אתר ישראלי שיש לו גם גרסה אנגלית עבר את הכאב הזה.

### שני דברים חדשים בקובץ

</div>

```css
/* color-mix – גוון ביניים בלי לחשב HEX ידנית */
thead th { background-color: color-mix(in srgb, var(--accent) 30%, var(--surface)); }

/* :has() – "הורה שיש בתוכו..." */
p:has(input:invalid:not(:placeholder-shown)) label { color: #b3261e; }
```

<div dir="rtl" align="right">

**`:has()` הוא הסלקטור שחיכו לו 20 שנה** – הוא בוחר **הורה לפי הילדים שלו**.
הכלל למעלה אומר: *"תווית שנמצאת בפסקה שיש בה שדה לא תקין שכבר הוקלד בו משהו"*.
בלעדיו זה היה דורש JavaScript.

</div>
<div dir="rtl" align="right">

## 🔨 שלב אחר שלב

### 1. אוספים את כל הערכים ל-`:root`

</div>

```css
:root {
  --brand-dark:  #4a2c17;
  --brand:       #7b4b2a;
  --accent:      #c9a227;
  --surface:     #ffffff;
  --bg:          #f5efe6;
  --ink:         #2b2b2b;
  --muted:       #6b6257;
  --line:        #e0d5c5;

  --font-body: system-ui, "Segoe UI", Arial, sans-serif;
  --font-head: Georgia, "Times New Roman", serif;
  --size-h1: clamp(1.9rem, 1.2rem + 3vw, 3rem);
  --size-h2: clamp(1.4rem, 1.1rem + 1.4vw, 1.75rem);

  --space-1: 6px;  --space-2: 12px; --space-3: 20px;
  --space-4: 32px; --space-5: 48px;

  --radius: 10px;
  --radius-lg: 14px;
  --shadow: 0 6px 18px rgb(74 44 23 / 15%);
  --speed: 0.2s;
}
```

<div dir="rtl" align="right">

**שימו לב לשמות.** `--brand-dark` ולא `--brown`. אם מחר החום יהפוך לירוק,
משתנה בשם `--brown` יהיה שקר. **שמות לפי תפקיד, לא לפי מראה.**

**וסולם המרווחים:** חמישה ערכים בלבד לכל האתר. זה מה שגורם לעיצוב להיראות
מכוון במקום אקראי – במקום 14px פה, 18px שם ו-22px במקום שלישי.

### 2. מחליפים בשימושים

</div>

```css
.site-header {
  padding: var(--space-2) var(--space-3);
  background-color: var(--brand-dark);
}
```

<div dir="rtl" align="right">

### 3. מוסיפים את בלוקי המצב הכהה

שני בלוקים: אחד ל-`prefers-color-scheme` (המערכת), אחד ל-`[data-theme="dark"]`
(בחירה מפורשת שנוסיף בשלב 29).

### 4. מחליפים לפיזי ← לוגי

</div>

```css
main {
  max-width: 1000px;
  margin-inline: auto;
  padding-inline: var(--space-3);
  padding-block: var(--space-4) var(--space-5);
}

blockquote { border-inline-start: 4px solid var(--accent); }
caption, th, td { text-align: start; }
.skip-link { inset-block-start: -100px; inset-inline-start: var(--space-2); }
```

<div dir="rtl" align="right">

### 5. מסדרים את הקובץ לפרקים

</div>

```css
/* 1. משתנים · 2. מצב כהה · 3. איפוס ובסיס · 4. פריסה · 5. כותרת וניווט
   6. תוכן · 7. טפסים · 8. תנועה · 9. מסכים קטנים */
```

<div dir="rtl" align="right">

**סדר קבוע = מוצאים כלל בשתי שניות.** בקובץ של 400 שורות זה ההבדל בין
לעבוד לבין לחפש.

## 👀 מה רואים במסך

- **במצב רגיל: שום דבר לא השתנה.** זו המטרה של ריפקטורינג.
- **הפעילו מצב כהה במערכת ההפעלה** (Windows: הגדרות ← התאמה אישית ← צבעים;
  או ב-DevTools ← ⋮ ← More tools ← Rendering ← `prefers-color-scheme`).
  **האתר כולו הופך לכהה** – רקעים, טקסט, מסגרות, גם הכרטיסים והטבלה.
- **גררו את רוחב החלון לאט** – הכותרת גדלה **ברציפות**, בלי קפיצה.

## 🎉 סוף חלק ה-CSS

**האתר שלנו כרגע:** ארבעה דפים מעוצבים, רספונסיביים, עם מצב כהה, אנימציות
ונגישות מקלדת. הוא נראה כמו אתר אמיתי של בית עסק.

**מה שהוא עדיין לא יודע לעשות:** להגיב. הכפתורים לא לוחצים, אין סינון בתפריט,
והטופס נבדק רק על ידי הדפדפן. [שלב 17](../step-17-js-variables/) מתחיל את JavaScript.

## ✋ אתגר לכיתה

1. שנו את `--brand-dark` ל-`#1f4d3d` (ירוק כהה) ורעננו. כמה מקומות באתר השתנו?
2. הוסיפו `--radius-sm: 6px` והשתמשו בו בשדות הטופס.
3. **שאלה:** למה `:root` ולא `body` להגדרת המשתנים?
4. **בדיקה:** בדקו את הניגודיות במצב כהה ב-DevTools. עוברת AA?

</div>
</div>

<details dir="rtl">
<summary><b>💡 הצגת הפתרון</b></summary>

<div dir="rtl" align="right">

**1.** הכותרת, הפוטר, כל הכותרות `h1`/`h2`, ה-`legend`, הכפתורים – **הכול בבת אחת.**
זה בדיוק העניין. עשו את זה בכיתה על המסך הגדול; זה הרגע שבו משתנים "נכנסים".

**2.** `:root { --radius-sm: 6px; }` ואז `input, select, textarea { border-radius: var(--radius-sm); }`

**3.** `:root` הוא אלמנט ה-`<html>` – **השורש**, מעל `<body>`. משתנים עוברים
בירושה כלפי מטה, אז הגדרה ב-`:root` מגיעה לכל דבר.

יש גם סיבה מעשית: **פסאודו-אלמנטים כמו `::backdrop`** (של `<dialog>`) לא
נמצאים בתוך `<body>`, ולכן לא יראו משתנה שהוגדר עליו.

**4.** בקובץ שלנו `--ink: #efe6da` על `--bg: #17110c` נותן יחס של בערך **13:1** –
הרבה מעל הדרישה (4.5:1 לטקסט רגיל).

**המלכודת הקלאסית במצב כהה:** לוקחים את הצבעים הבהירים ו"רק הופכים" אותם.
צבע הדגשה שעבד יפה על רקע בהיר הופך לבלתי קריא על כהה. **לכן ה-`--accent`
שלנו בהיר יותר במצב כהה** (`#e0b93f` במקום `#c9a227`) – זו החלטה מודעת.

</div>
</details>

## 🔍 טעויות שראינו בכיתה

| הטעות | מה קורה |
|--------|----------|
| `background: --brand` בלי `var()` | לא עובד. חייב `var(--brand)` |
| `--Brand-Dark` מול `--brand-dark` | משתני CSS **רגישים לרישיות** |
| שמות לפי צבע (`--brown`) | הופך לשקר ברגע שהמותג משתנה |
| משתנים על `body` | פסאודו-אלמנטים מסוימים לא רואים אותם |
| מצב כהה על ידי היפוך צבעים | ניגודיות נשברת. בוחרים ערכים מחדש |
| `font-size: 4vw` בלי `clamp` | טקסט זעיר בטלפון, ענק במסך רחב, וזום לא עובד |
